С решения 0041 карту собирает `LiveMap` из `core`: файлы — наблюдаемые значения, объект —
вычисляемые поля. На сервере источник файлов — `DiskFiles` с вотчером (пачка ждёт тишины
~40 мс), на клиенте — мост (`watchMapFile`, `watchMapFolder`). Свои записи сервера — через
`MapModel.writer` (директива, состояние, реплика, `map-state.json`) — видны сразу. Кэш и логи
метрик пишутся мимо обёртки: в модель они не входят.

На чём спотыкаются:

- **Тест с фейковым `watch: () => () => undefined`** не увидит файл, который тест дописал в
  дерево сам после первого чтения: вотчер молчит. Либо пиши через `model.writer(files)`, либо
  зови `model.reload(ref)`, либо заводи новую модель на каждый вызов (так сделан `readMap` в
  `map-model.test.ts` и `metric-store.test.ts`).
- **Агент записал файл карты `Write`-ом и сразу зовёт MCP** — модель могла ещё не получить
  событие. `DirectiveLocator` и `read_object`/`read_index` при промахе по адресу перечитывают
  карту и ищут второй раз; в остальном — кнопка «↻» или повтор вызова.
- **MobX забывает вычисленное без наблюдателя.** Геттер, который в каком-то состоянии не читает
  вычисляемое поле (например, «пока не готово — `undefined`», не заглянув в значение), снимает с
  него наблюдателя, и после этого то же значение собирается новым объектом — подписчики видят
  лишнюю пересборку. Поэтому `LiveMap.snapshot` читает значение всегда, а готовность — отдельно.
- Сравнить модель со старым чтением можно было только временным тестом: старый `read-map.ts`
  берётся из git (`git show b810c07:packages/abstract-server/src/features/map-object/application/use-cases/read-map.ts`)
  и кладётся рядом с правкой импортов; сырые поля `raw*` старого вывода перед сравнением
  отбрасываются. На настоящей карте 2026-09-23 результат совпал целиком.
