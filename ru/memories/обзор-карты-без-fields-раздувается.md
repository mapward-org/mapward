Совет «начни с обзора: `read_object` с глубиной и без метрик» на корне этой карты давал
~55 КБ и уезжал в файл, хотя `metrics: []` стоит. Вес дают не значения метрик — их нет, — а
поля, повторяющиеся на каждом из двух десятков объектов.

С 2026-09-20 `layout` и `workflow` приходят только у **верхнего** объекта ответа (решение
`0022`), и половина веса ушла. Осталось то, что у каждого объекта своё: `actions`, `props`,
`layers`. Поэтому `fields` по-прежнему обязателен:

```json
{ "depth": 2, "metrics": [],
  "fields": ["address", "name", "prototypeName", "path", "props", "directives"] }
```

Так обзор этой карты весит ~14 КБ вместо 55. Проекция, не задевшая у ребёнка ни одного поля,
списка детей больше не порождает — `children: [{}, {}, …]` в ответе не будет.

`workflow` и `actions` добавлять в проекцию только когда они и есть вопрос; воркфлоу
раскрытого ребёнка так не достанется вовсе — его спрашивают своим вызовом.

Проверено 2026-09-20 на `mapward://` карты «Mapward (ru)».
