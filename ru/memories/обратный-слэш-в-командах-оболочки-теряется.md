---
description: удвоенный обратный слэш в команде оболочки приезжает одинарным — код правь файлом-скриптом, не строкой команды
---

Правка через `sed -e '...'` или `node -e "..."` с регуляркой портит обратные слэши: `[\/]`
доезжает до файла как `[\/]`, то есть класс символов молча теряет один из двух. Заметно это
не сразу — код остаётся валидным, просто проверяет не то.

Надёжный путь для правок кода: положить старый и новый кусок в файлы и заменить их скриптом,
который читает эти файлы с диска и требует ровно одного совпадения. Тогда в командную строку
не попадает ни одного спецсимвола.

Класть текст в файл лучше инструментом записи, а не heredoc'ом: на длинном куске (десятки
строк markdown по-русски) `cat > file << 'EOF'` падает с `unexpected EOF while looking for
matching '`, не написав ничего. Короткие heredoc'ы проходят, но полагаться на это не стоит —
надёжно так: `Write` во временную папку, потом `cat временный >> целевой`.

Если обратный слэш нужен внутри самого скрипта — собирать его из `String.fromCharCode(92)`.
