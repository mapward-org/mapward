`mcp-http.ts` держал ожидающие ответы в `Map` по `id` **из тела запроса клиента**. У http
каждый вызов — отдельное соединение, и клиент вправе нумеровать их с единицы: два
одновременных вызова с одинаковым `id` затирали друг друга — первый повисал без ответа, а его
результат уезжал в response второго.

Снаружи это выглядело как нормальный ответ про **другой объект**: ошибки нет, поля на месте,
видно только по `address`.

Починено 2026-09-20 директивой `улучшение-mcp`: ключ теперь свой (`http-N`), наружу
возвращается клиентский `id`. Тест — `apps/vscode-extension/src/apps/extension/mcp-http.test.ts`.

**Но**: живой MCP обслуживает `dist` открытого расширения (см.
[живой-mcp-это-собранная-сборка](живой-mcp-это-собранная-сборка.md)). Пока расширение не
пересобрано и не перезапущено, баг в сессии остаётся — сверяй `address` в каждом ответе, а на
важном чтении зови по одному. По stdio (`mapward mcp`, cli) этого не было никогда: там одно
соединение и ответы просто пишутся в поток.
