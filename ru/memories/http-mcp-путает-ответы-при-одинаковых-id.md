description: MCP расширения ключует ответы по клиентскому id — два параллельных вызова с одинаковым id получают чужие ответы; зови по одному или сверяй address
---

`mcp-http.ts` держит ожидающие ответы в `Map` по `id` **из тела запроса клиента**
(`waiting.set(id, …)`). У http каждый вызов — отдельное соединение, и клиент вправе нумеровать
их с единицы. Два одновременных вызова с одинаковым `id` затирают друг друга: первый повисает
без ответа, а его результат уезжает в response второго.

Снаружи это выглядит как нормальный ответ про **другой объект** — ошибки нет, поля на месте.
Единственное, по чему видно, — `address` в ответе `read_object`. Повтор того же вызова в
одиночку отвечает правильно.

Пока не починено: несколько вызовов карты в одном сообщении шли параллельно — сверяй `address`
в каждом ответе, а на важном чтении зови по одному. По stdio (`mapward mcp`, cli) этого нет:
там одно соединение и ответы просто пишутся в поток.
