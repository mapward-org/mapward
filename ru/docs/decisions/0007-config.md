# `mapward.json`

Карту надо сначала найти. Инструмент запускается из терминала, из расширения, из CI —
cwd везде разный, и класть в него опору нельзя. Поэтому опора одна: файл настройки в
проекте.

```json
{
  "maps": [
    { "mapUrl": "ru/map", "baseUrl": "." }
  ]
}
```

`mapUrl` — директория карты, обязателен
`baseUrl` — корень проекта этой карты, от него резолвится `@`, дефолт `.`

Оба пути считаются **от папки самого `mapward.json`**. Это единственное место, которое
известно точно ещё до того, как что-то прочитано.

Здесь же лежат настройки MCP-сервера — его адрес и запреты на сеть, см. решение
[0009](0009-mcp.md).

## Почему список, а не одна карта

Карт в проекте бывает несколько: у монорепы своя карта на подсистему, у документации на
двух языках — своя на язык. 

У каждой карты свой `baseUrl`, поэтому **`@` у каждой карты свой** — он разрешается от
той карты, которой принадлежит объект, см. решение [0005](0005-addressing.md).


## Поиск

От текущей директории вверх до корня файловой системы, первый найденный выигрывает.
Так же ищут свои конфиги git и пакетные менеджеры, привычка уже есть.

Конфига нет — карты нет. CLI останавливается с сообщением, где искал. Что делает
редактор, у которого cwd нет вовсе, — в решении [0008](0008-workspaces.md).

## Зачем `baseUrl` отдельно

Обычно он совпадает с папкой конфига, поэтому и дефолт `.`. Отдельным параметром он
нужен, когда конфиг лежит не в корне — например в подпапке монорепы, а код выше.
