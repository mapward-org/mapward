# `mapward.json`

Карту надо сначала найти. Инструмент запускается из терминала, из расширения, из CI —
cwd везде разный, и класть в него опору нельзя. Поэтому опора одна: файл настройки в
проекте.

```json
{
  "mapUrl": "ru/map",
  "baseUrl": "."
}
```

`mapUrl` — директория карты, дефолт `mapward`
`baseUrl` — корень проекта, от него резолвится `@`, дефолт `.`

Оба пути считаются **от папки самого `mapward.json`**. Это единственное место, которое
известно точно ещё до того, как что-то прочитано.

## Поиск

От текущей директории вверх до корня файловой системы, первый найденный выигрывает.
Так же ищут свои конфиги git и пакетные менеджеры, привычка уже есть.

У расширения редактора cwd нет — оно начинает от корня воркспейса.

Конфига нет — карты нет. CLI останавливается с сообщением, где искал; расширение
предлагает создать конфиг.

## Зачем `baseUrl` отдельно

Обычно он совпадает с папкой конфига, поэтому и дефолт `.`. Отдельным параметром он
нужен, когда конфиг лежит не в корне — например в подпапке монорепы, а код выше.

`@` в адресах — это и есть `baseUrl`, см. решение [0005](0005-addressing.md). До него
корень проекта приходилось хранить в `props` корня карты и считать `../..` от неё:
формула ломалась молча, стоило карте переехать глубже.

## Одна карта

`mapUrl` один. Если карт понадобится несколько, это отдельное решение — сейчас нет
ни одного случая, на котором можно проверить, чем они должны отличаться.
