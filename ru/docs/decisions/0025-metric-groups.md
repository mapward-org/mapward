# Группы метрик — вкладки объекта, а не фильтр вида

Метрик у объекта стало больше, чем помещается на экран сразу, и они разные по цене. Дерево
файлов и версия пакета считаются мгновенно, а проверка архитектуры поднимает агента на минуты.
Сейчас открытие объекта поднимает все не-`manual` метрики разом: подписка на объект и означает
«объект открыт» — [0013](0013-metrics-store.md).

Поэтому метрики объекта раскладываются по группам, и группа показывается вкладкой.

## Группа живёт у объекта

Объявляется в `_index.json`, рядом с раскладками:

```json
"metric-groups": {
  "mode": "merge",
  "groups": [
    { "key": "код", "label": "Код", "metrics": ["files", "tests"] },
    {
      "key": "тяжёлое",
      "description": "Проверки агентом, считаются минутами",
      "metrics": ["architecture", "drift"],
      "details-metrics-layout": { "areas": [["architecture"], ["drift"]] }
    }
  ]
}
```

Не у метрики: у группы есть описание, порядок вкладок и своя раскладка, а метрике из
`shared-metrics` положить их некуда — она достаётся многим объектам сразу, и группа приезжала бы
вместе с ней туда, где такой вкладки нет. Метрика знает, что она считает; что показывать вместе —
свойство объекта.

Поля группы: `key` — имя для состояния и для MCP, `label` — подпись вкладки (без неё вкладка
подписана ключом), `description` — markdown над сеткой ([0027](0027-markdown-display.md)),
`metrics` — ключи, они же порядок, `details-metrics-layout` — раскладка вкладки; без неё берётся
раскладка объекта.

Наследуются группы, как этапы воркфлоу ([0017](0017-directive-workflow.md)): `mode` говорит,
мерджить прототиповы или заменить целиком, а своя группа с тем же ключом переопределяет
прототипову **целиком**, а не по полям. Иначе «убрать метрику из вкладки» пришлось бы писать
как «перечислить все, кроме одной», и список у наследника расходился бы с прототипом молча.

## Метрика вне вкладок не показывается и не собирается

Групп у объекта нет — показываются все метрики, как раньше. Группы есть — метрика, не названная
ни в одной, не показывается вовсе и не собирается.

Это не побочный эффект, а способ: унаследованную от прототипа метрику так можно не использовать,
не отказываясь от самого прототипа. Прежде выбор был между «взять прототип целиком» и «не брать
его»; теперь набор метрик — то же наследуемое свойство, что раскладка.

## Вкладка — это то, что открыто

Активная вкладка едет в подписку `watchMetrics`, и сервер собирает только её метрики. Значит
«объект открыт» превращается в «открыта эта вкладка»: у закрытой не тикают интервалы и не живут
вотчеры встроенных шагов ([0023](0023-builtin-transforms-and-git.md)), а `on-display`
срабатывает при первом переключении на неё.

Переключение вкладки — это отписка и подписка, то есть то же самое, что уход на соседний объект
и возврат обратно. Значения при этом остаются: они живут в сторе, а не в виде
([0013](0013-metrics-store.md)), поэтому возврат на вкладку показывает собранное раньше и, если
оно протухло, запускает прогон — ровно как переход по карте.

Цена названа вслух: вкладка, которую не открывают, не обновляется никогда. Это и есть то, ради
чего группы заводились.

## Агенту вкладка — набор, а не экран

`read_object` отдаёт перечень вкладок полем `groups` и принимает `group`: приходят метрики
названной. Без `group` приходят метрики всех вкладок — и только они: метрика вне вкладок не
приходит агенту по той же причине, по которой её не видит человек.

Ключи, названные в `metrics`, побеждают вкладки: агент, назвавший метрику по имени, знает, что
просит. Промах по ключу вкладки — ошибка с перечнем, а не молчаливый откат на первую: откат отдал
бы чужие метрики под видом заказанных.

## Инвариант

Метрика, не названная ни в одной группе объекта с группами, не появляется ни на экране, ни в
ответе `read_object` без явного `metrics`, и её коллекторы не запускаются. Появилась — группы
превратились в фильтр вида, и экономия, ради которой они заведены, исчезла.

Одна вкладка открыта всегда: объект с группами не бывает «без выбранной вкладки».
