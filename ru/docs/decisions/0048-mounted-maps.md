# Подключённые карты

> Черновик агента по директиве `2026-09-28-0025-подкарты.md` — правит автор.

Личная карта держит все проекты, а часть знания о проекте хочется хранить в карте в его
репозитории. Корневая карта подключает карту проекта и ссылается на её объекты, но дерево с ней
не сливает: у вложенной карты `mapward://` и `@` значили бы другое, чем в её собственном
репозитории.

## Как подключают

Подключение — свойство карты, поэтому живёт в её записи в `maps` ([0007](0007-config.md)):

```json
{ "maps": [{ "mapUrl": "my-space-map", "mounts": { "leafer": "./leafer/mapward.json[0]" } }] }
```

Значение — путь к `mapward.json` проекта и номер карты в его `maps`, по позиции: номер не
зависит от того, как карта назвала себя. Без номера — первая. Путь считается от папки конфига,
где подключение написано. Карта проекта берётся со своим корнем проекта, прототипами и
подключениями — как при открытии проекта отдельно. Про родителя она не знает.

Ошибка настройки — не тот файл, нет номера, нет проекта на диске — остаётся у своего имени:
родитель работает, ссылки на это имя показывают причину на месте.

## Адрес

Имя подключения стоит перед двоеточием ([0005](0005-addressing.md)):

```
mapward://leafer:/arch                 объект карты проекта
mapward://leafer:/arch#props.name      его поле
mapward://leafer:@/src                 файлы проекта — её @
```

Двоеточия в имени папки на Windows не бывает, поэтому с адресом своего объекта это не спутать.
`leafer:~` — ошибка: «этот объект» в чужой карте смысла не имеет. Подключения не транзитивны:
имя ищется у карты, которой принадлежит объект со ссылкой, а подключения проекта работают
внутри проекта.

Внутри системы объект — пара «карта + её собственный адрес». Адрес с именем — только форма
записи в файлах родителя.

## Что даёт

Все три вида ссылок: ссылка и связь на холсте, подстановка поля и `extends`.

Подстановка берёт поле объекта проекта уже посчитанным от его карты: `@` в нём — корень проекта.
Прототип из карты проекта наследуется по общему правилу ([0006](0006-substitution.md)): `@` в
его метриках — корень наследника. Слои и владельцы унаследованного пишутся адресом с именем
подключения — по ним видно, где править.

На холсте родителя объект проекта — всегда один узел, не группа, помеченный именем карты.
Попадает он туда только ссылкой и концом связи. Связь, проведённая на холсте родителя, пишется в
карту родителя. Связи самого проекта рисуются, когда оба их конца лежат на холсте. Ссылка на
пропавший объект остаётся узлом с причиной.

Сам объект проекта через вьюху родителя не переносят, не переименовывают и не удаляют: это
переписало бы файлы другого репозитория мимо его карты.

## Где видно

В боковой панели подключённой карты нет: что нужно, покажут метрики. Объект проекта открывается
переходом на том же экране, своим кадром — со своей картой, прогонами и директивами; «назад» и
первая крошка возвращают в родителя.

MCP принимает адрес с именем везде, где принимает адрес, и отвечает, из какой карты объект.
`list_maps` показывает подключения у каждой карты.

## Инвариант

Карта проекта, открытая в своём репозитории, работает так же, как подключённая: ни один её
адрес не зависит от того, кто её подключил.
