# Логи плагинов и сквозной трейс

> Черновик агента по директиве `2026-11-01-1302-логи-плагинов.md` — правит автор.

Ход экшона, метрики или вызова плагина толком негде было посмотреть. Прогон писался только при
запуске через экшон, stderr плагина держался в памяти хвостом, вызовы MCP не писались вовсе. А
смотреть ход нужно и человеку, и агенту: что сейчас идёт, где упало, что сделал агент, которого
запустил экшон.

## Логи и запуски разделены

Логи — файлы в `.mapward/logs/` карты: файл на плагин (`<плагин>.log`) и `mapward.log` — для самой
платформы и входов MCP. Запуск — трейс. Логи льются в файлы всегда, откуда бы ни позвали метод, а
запуск — это фильтр по трейсу в потоке логов.

Формат — JSON Lines: строка несёт трейс, номер вызова, объект, плагин, метод, время и вид записи.
Пишет одна платформа: плагин зовёт свой `log`, а контекст вызова к строке приклеивает она. Так
строку не забудут пометить, и писатель в файл один.

Агенты читают логи путём к файлу, grep по трейсу или объекту. Отдельного инструмента MCP для
логов нет: файл и grep агент и так умеет.

## Трейс сквозной

Любой вход в платформу заводит трейс: кнопка экшона, строка списка, `run_action` и другие
инструменты MCP, `mapward action`, сбор метрики. Каждый вызов метода плагина идёт внутри трейса со
своим номером и помнит родителя.

Трейс едет вниз сам: вызов другого плагина и просьбы к платформе — в трейсе вызова, откуда их
сделали; процессам `shell` и `agent` — переменной `MAPWARD_TRACE`; MCP принимает его с подключения,
заголовком `x-mapward-trace`, — `agent` запускает Claude с конфигом MCP, где трейс и стоит
заголовком. Вызов MCP без трейса заводит свой. Так агент, которого запустил экшон, и всё, что он
сделал через карту, лежат в трейсе экшона.

Отмена трейса снимает все его идущие вызовы, вложенные тоже: экшон, который агент экшона запустил
через MCP, останавливается вместе с ним. Обёртки для отмены не нужно — это по-прежнему отписка.

## Контекст вызова в API плагина

Метод получает свой `ctx` на вызов: `ctx.log(...)` — ход, `ctx.log.error(...)` — ошибка,
`ctx.output(...)` — вывод, `ctx.step(имя)` — начался шаг, `ctx.signal` — сигнал отмены, `ctx.call`
— номер вызова и трейс. Просьбы из такого `ctx` уходят в трейсе вызова. У `init` и `dispose` —
`ctx` процесса: его `log` и stderr ложатся в файл плагина без вызова.

Сообщения хода в потоке (`progress: step | out | log`) ушли: в потоке теперь только итог. Ход —
дело лога, а не ответа: иначе его видно только тому, кто позвал через экшон.

Дока плагинов показывает `ctx.signal` и `ctx.log` в первом же примере и советует проверять отмену
в долгой работе и почаще писать ход. Отписка снимает поток, а работу, начатую мимо него, гасит
только сам плагин; по ходу человек и агент находят, где упало.

## Хранение — по размеру

10 МБ на файл и одна предыдущая копия `.1`. Старые прогоны не нужны: логи смотрят по последним.

## Прогоны — из строк лога

Прогон остаётся понятием и экраном, но своего хранилища у него нет: `.mapward/runs/` уходит.
Начало и конец трейса — кто, объект, данные формы, конфиг, статус, итог — ложатся строками в
`mapward.log`; прогон экшона или метрики собирается из строк его трейса. Номер прогона — номер
трейса. Трейс без строки конца после перезапуска окна показывается прерванным. Прогон живёт, пока
его строки в логе.

Красная точка метрики открывает трейс, если он ещё в логе; иначе причина видна в значении метрики.

## Экран прогонов — интерфейс к логам

Экран прогонов становится интерфейсом к логам с фильтрами: по объекту и по плагину на объекте.
«Все логи» и «по плагину все» — дополнительный вид для отладки, а не основной: карта строится
зонами, и чужое в основном виде — шум.

## Отвергнуто

- **Прогоны под снос, логи как у nginx** — обычный, ошибки, свой у mapward. Экран прогонов нужен:
  по нему видно, кто запустил и с чем. Ему не нужно своё хранилище.
- **Общий вид «все логи» основным** — довод `0038` про зоны остаётся.

## Что перекрыто

- [0038](0038-executable-actions.md), раздел «Прогоны — операционка, локально»: прогон не лежит в
  `.mapward/runs/` по двадцать последних — он собирается из строк лога, хранение ограничено
  размером лога. Довод «общего списка на карту нет» остаётся для основного вида.
- [0038](0038-executable-actions.md), инвариант: прогон экшона виден на экране прогонов его
  объекта, пока его трейс в логе.

## Инвариант

Всё, что написал плагин, лежит в `.mapward/logs/<плагин>.log` строкой с трейсом, а вход MCP — в
`mapward.log`. Прогон собирается из строк лога, и у прогонов нет своих файлов. Отмена трейса
снимает его вызовы, вложенные тоже.
