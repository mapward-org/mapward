# Адресация

Адресация одинаковая во всей карте: в `extends` объекта, в `extends` метрики,
в `from` и `to` связей, в `link` форм отображения, в подстановках

Адреса объектов карты и пути к файлам легко перепутать, поэтому у карты свои схемы.
Схема говорит и откуда считаем, и что получим — путь или значение

```
mapward://prototypes/package               путь до объекта от корня карты
mapward://prototypes/package#props.name    значение поля этого объекта
mapward://~                                путь до текущего объекта
mapward://~#props.name                     значение своего props
mapward://~/relations/relation             путь до ребёнка
mapward://~/relations/relation#props.from  значение props ребёнка
mapward://@                                корень проекта — baseUrl этой карты
mapward://@/packages/core                  путь от корня проекта
```

`~` значит «этот обьект», без него путь от корня карты. Слэши идут по объектам,
решётка отделяет путь по полям `_index.json`. Без решётки получаем путь, с ней значение

Пустой путь перед решёткой это корень карты: `mapward://#props.name`

Код лежит вне карты, и чтобы не писать `../..` в каждой метрике, есть `@` — корень
проекта. Это `baseUrl` из `mapward.json`, свой у каждой карты: `@` разрешается от той
карты, которой принадлежит объект, см. решение [0007](0007-config.md)

```json
{ "kind": "read-dir", "basePath": "${{ mapward://@ }}/packages/core" }
```

За `@` лежит код, а не объекты карты, полей `_index.json` там нет. Поэтому `@` даёт
только путь, решётка с ним не работает: `mapward://@/packages/core#props.name` — ошибка

Переезд карты правит одну строку в `mapward.json`

### Адрес употребляется двумя способами

**Ссылка на объект карты.** Обычно значением поля, без интерполяции. Резолвится по месту:
при наследовании, при переходе, при валидации

```json
{ "extends": "mapward://prototypes/package" }
{ "props": { "from": "mapward://core", "to": "mapward://vscode-application" } }
```

**Путь или значение в интерполяции.** Подставляется в строку, см. решение [0006](0006-substitution.md)

Адрес без решётки даёт **абсолютный файловый путь**: `mapward://` — корень карты,
`mapward://~` — папка текущего объекта. Относительные пути в конфигах иначе не от чего
считать, cwd мы не контролируем

```json
{ "run": "pnpm test --filter ${{ mapward://~#props.name }}" }
{ "basePath": "${{ mapward://core }}/relations" }
```

### Абсолютные пути

В extends from to можно указывать и обычные файловые пути и ссылки в интернет.

Если ссылки абсолютные проблем нет. Если относительные они резолвятся от cwd, это достаточно не предсказуемо поэтому советуем использовать ссылки относительно корня карты


Абсолютные пути разрешены и ничем не ограничены. Что они не переживут переезда
на другую машину — забота того, кто их написал, а не карты
