# План — это архитектурные решения

> Черновик агента по директиве `2026-09-23-1804-улучшение-промптов.md` — правит автор.

У большой задачи план держал хороший уровень, а у маленькой оставался почти таким же длинным и
спускался в мелочь: три круга про правки десяти файлов в одном модуле. Причина в самом этапе.
Кусок плана был привязан к модулю и обязан был показать, где правка, и всё, что агент решил сам.
Поэтому подробность росла с числом файлов, а не с числом решений.

## Кусок — одно решение с уровнем

Кусок плана — одно архитектурное решение, первой строкой его уровень:

- enterprise — как задача ложится в дело целиком;
- solution — итог архитектуры решения: какие системы участвуют и как договариваются;
- software — архитектура кода: какие модули, какие связи;
- platform — переиспользуемая платформа, её публичное API и требования;
- code — подход к самому коду: чистые функции, реактивность, декларативно или императивно.

Уровень, на котором решать нечего, пропускается. У маленькой задачи enterprise и solution обычно
нет, а software хотя бы один бывает.

В план попадает публичное API, новые модули и понятия, связи и решения уровня кода — это почти
всегда и есть то, что автору интересно проверить заранее. Не попадают файлы, строки, имена и
раскладка внутри модуля. Модуль называется адресом папки, только когда решение про него. В код
спускаются по просьбе автора.

Цена принята: неудачное имя или раскладку автор увидит уже в диффе Реализации.

## Брейншторм не меняется

Вопросы Брейншторма уровня не помечают: это разговор о задаче, а не запись решений, и он не
мешал. Вопросы уровня code задавать можно.

## Что перекрыто

  со ссылками на папки, и план не обязан показывать всё, что агент решил сам.

## Инвариант

Каждый кусок Плана — одно решение с названным уровнем. Кусок, в котором перечислены файлы или
правки по строкам без просьбы автора, — нарушение.
