# Завести пакет

Пакет — это три вещи сразу: папка в `packages/`, объект карты и док об устройстве. Порядок ниже
доводит до всех трёх. Это меняет устройство проекта, поэтому идёт директивой, а не экшоном
(решение [0038](../decisions/0038-executable-actions.md)). Пакет, заведённый по нему, не нарушает ни инвариант `0014`
(направление зависимостей), ни `0015` (слои и док на своём объекте).

Перед запуском в `_index.json` объекта заполнены props:

- `codePath` — где лежит пакет, от корня репозитория: `packages/<имя>`
- `packageName` — имя в npm: `@mapward/<имя>`
- `architectureDoc` — док об устройстве: `ru/docs/architecture/<имя>.md`
- `docsPath` — общий док про границы, у всех пакетов один: `ru/docs/architecture/packages.md`

`fullPath` считает прототип, руками его не пишут. Сам объект карты — предусловие, а не шаг:
директива заводится на объекте, значит `_index.json` с `extends: mapward://prototypes/package`
уже есть.

## Если по `codePath` уже что-то лежит

Живой код не переписывается. Пройди по списку ниже и заведи только недостающее — у пакета,
появившегося до этого порядка, обычно нет метрик на объекте или строки в `ALLOWED`. Что есть,
остаётся как есть, даже если сделал бы иначе: расхождения с устройством потом покажет метрика,
и это дешевле, чем переписанный без спроса пакет.

## Каркас

`package.json` — состав такой же, как у остальных пакетов:

```json
{
  "name": "@mapward/<имя>",
  "version": "0.0.0",
  "private": true,
  "description": "<одна строка по-английски: что внутри и чего внутри нет>",
  "files": ["dist"],
  "type": "module",
  "main": "./dist/index.mjs",
  "types": "./dist/index.d.mts",
  "exports": { ".": { "types": "./dist/index.d.mts", "default": "./dist/index.mjs" } },
  "publishConfig": { "access": "public" },
  "scripts": { "build": "tsdown", "dev": "tsdown --watch", "typecheck": "tsc" },
  "devDependencies": {
    "tsdown": "catalog:",
    "typescript": "catalog:",
    "unrun": "catalog:"
  }
}
```

Версии — только `catalog:` и `workspace:*`. Диапазон, написанный руками, означает, что пакет
разъедется с остальными по версии инструмента, а монорепа, где такое случилось, монорепа
только по раскладке папок (`pnpm-workspace.yaml`).

`tsconfig.json`:

```json
{ "extends": "../../tsconfig.base.json", "include": ["src/**/*.ts", "tsdown.config.ts"] }
```

`tsdown.config.ts` — `entry: "src/index.ts"`, `format: "esm"`, `dts: true`.

Регистрировать пакет негде: `pnpm-workspace.yaml` и корневой `tsconfig.json` берут
`packages/*` глобом. После заведения — `pnpm install`, иначе `workspace:*` не свяжется.

## Слои заводятся сразу, пустыми

По `0015`, с `.gitkeep`: форма на старте важнее наполнения, переезжающему коду есть куда лечь.
Раскладка берётся по роли пакета — серверная, клиентская или как у `core`; все три описаны
в `0015` и в `ru/docs/architecture/`. Пакет, который ни то, ни другое, слои не выдумывает:
заводит то, что ему правда нужно, и описывает это в своём доке.

В `index.ts` — то, что пакет отдаёт наружу на сегодня. Совсем пустой файл оставлять не стоит:
`dts` соберёт пустой тип, а линтер это заметит раньше человека.

## Направление зависимостей

`0014` задаёт направление, а не обязанность. Клиент не знает сервера, пакет не знает
приложений, в `core` переезжает то, что доказало необходимость. Зависимость на
`@mapward/core` ставится, когда она нужна, а не по умолчанию — `@mapward/docs` живёт без неё.

Пакет вписывается в `ALLOWED` в `tests/dependency-direction.test.ts` — теми `@mapward/*`, от
которых он зависит на самом деле. Без этого тест падает с «нет правила для <имя>», и это не
придирка теста: список в нём и есть инвариант `0014`.

На каждую зависимость — объект связи, `ru/map/relations/<откуда>-to-<куда>/_index.json`:

```json
{
  "name": "использует",
  "props": { "from": "mapward://packages/<a>", "to": "mapward://packages/<b>" }
}
```

## Док и метрики

По `0015` у пакета есть док об устройстве, ссылка на него и валидация устройства. Заводятся
все три, иначе пакет рождается с нарушенным инвариантом:

- `ru/docs/architecture/<имя>.md` по пути из `architectureDoc` — слои, что в каждом лежит,
  направление импортов, место реализаций портов. Каркас разделов заводит агент, смысл
  дописывает человек: док — проекция решений (`0012`), а не пересказ состава папок;
- строка в `ru/docs/architecture/README.md` — списком доков пользуются, и пропущенного в нём
  дока нет;
- `_metrics/architecture-drift/config.json` у объекта карты, одной строкой:

```json
{ "extends": "mapward://shared-metrics/architecture-drift" }
```

Метрика «Архитектура» заводить не нужна — она приезжает от прототипа и сама показывает
`architectureDoc`. Прототипу хватает подстановки: путь у каждого наследника свой, а выражение
в конфиге одно.

Док по `docsPath` не трогается. Там `ru/docs/architecture/packages.md` — общий док про границы
между пакетами; описание отдельного пакета в нём не живёт, и дописанное туда «что за пакет и
зачем» ломает ровно то разделение, ради которого `0015` разводил папки.

## Чего не делать

Не публиковать и не поднимать версию — этим занимается экшон «Опубликовать версию».

Не заводить пакет впрок. Пустой пакет в репозитории — то же обещание, что и пустая папка,
и стоит оно ровно столько же (`0014`).
