# component

API окна для метрики-компонента — решение
[0037](../decisions/0037-component-display.md): то, чем компонент говорит с платформой. Его ставят
в проект dev-зависимостью, чтобы компонент метрики проверялся компилятором, а не угадывался.

```
src/
  index.ts    пропсы компонентов (метрики, раскладки, формы экшона) и объявления API окна:
              хуки плагинов, навигация, состояние вида, экшоны, карточка объекта
```

Кода здесь нет, только типы и `declare`: на карте `import … from "@mapward/component"` подменяет
клиент. Реализация живёт в `abstract-react-client` (`features/metrics/compose/component-kit.tsx`,
хуки — `features/metrics/plugin-kit.ts`) и проверяется против этих типов `satisfies` —
разойдутся, не соберётся клиент, а не сломается чужой компонент.

В пакете только то, что говорит с платформой: `usePlugin`, `useQuery`, `useStream`,
`useMutation`, `useNavigation`, `useViewState`, `useAction`, `ObjectCard` и типы пропсов
(`MetricProps`, `LayoutProps`, `ActionFormProps`). `useAction(экшон, inputs?)` — экшон по ключу
объекта ячейки или по адресу: подпись, сколько прогонов идёт, нет ли его и запуск тем же путём,
что из шапки объекта; находят и запускают его экшоны клиента (`ActionsStore.handle`), метрикам
они приходят портом. `ObjectCard` — карточка объекта по адресу: ею холст плагина `objects-map`
рисует узлы с полным превью. Открыть ссылку, как карта, — `useNavigation()`: в клиенте он зовёт
встроенный плагин `navigation` карты, а на ответ «объект» переходит экран.

Готовых кирпичей здесь нет. Список, дерево, markdown, точка статуса, сетка раскладки, кнопка
экшона — исходники встроенного плагина `views` (`packages/plugins/registry/views/bricks/`, в
карте — копия `_plugins/views/bricks/`): компонент берёт их относительным импортом, и сборщик
собирает их внутрь него. Это код проекта по модели shadcn — его правят под себя, а клиент свои
экраны рисует своими вью: двойной код здесь осознанный. Что кирпичи знают из своего только этот
пакет, стережёт `tests/dependency-direction.test.ts`.

Пакет ни от кого из своих не зависит: он публикуется для проектов, у которых mapward нет в
зависимостях, и тянуть за собой `core` ему незачем. React — только типами, peer-зависимостью
`@types/react`. Потоки методов плагина — `Observable` из rxjs: `rxjs` — зависимость пакета ради
типов, а на карте его, как React, отдаёт клиент (`Provided` в `component-display.tsx`).
