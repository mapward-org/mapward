# Архитектура

Здесь внешний контур: из чего инструмент собран и как части разговаривают. Как устроен каждый
пакет внутри — в [`../architecture/`](../architecture/), по доку на пакет.

Mapward разделён на сервер и клиент — не по процессам, а по знанию. Сервер знает модель карты
и ничего не знает про экран; клиент знает экран и ничего не знает про среду. В одном процессе
они живут или в разных, решает приложение. Решение [0014](../decisions/0014-client-server.md).

```
        vscode-extension    |    cli
                     \        /
                       [ mcp ]
                     /        \
  abstract-react-client  |  abstract-server
                     \        /
                        core
```

## Пакеты

| Пакет | Что внутри |
| --- | --- |
| `core` | то, что обеим сторонам нужно понимать одинаково: типы контракта и согласованная логика |
| `abstract-server` | юзкейсы и домен карты; среда приходит портами |
| `abstract-react-client` | интерфейс на React и tailwind; платформа приходит портами |
| `display` | типы дисплея-компонента метрики для чужих проектов; кода нет, ни от кого не зависит — [0037](../decisions/0037-component-display.md) |
| `mcp` | адаптеры к серверу, общие для платформ; заводится, когда адаптеров станет больше одного |

Устройство внутри: [core](../architecture/core.md),
[abstract-server](../architecture/abstract-server.md),
[abstract-react-client](../architecture/abstract-react-client.md),
[расширение](../architecture/vscode-extension.md), [cli](../architecture/cli.md).

Приложения реализуют порты: `vscode-extension` — обеих сторон, `cli` — сервера.

Зависимости идут в одну сторону: `core` ни от кого, пакеты от `core`, приложения от пакетов.
Клиент сервера не знает — всё, что он о нём знает, описано в `core`.

В `core` попадает не всё общее, а только то, что доказало необходимость: дублирование по
умолчанию, вынос — по реальному прецеденту переиспользования и с проверкой человеком. Чистота
пропуском не является: слияние `extends`, подстановки, глобы и промпты чистые, но это сервер;
раскладка сетки и иконки файлов — клиент.

## Порты

Сервер просит у среды файлы и слежение за ними, запуск процессов оболочки, запуск агента и
время — ровно то, чем собирается метрика ([0004](../decisions/0004-metrics-schema.md)).

Клиент просит у хоста открыть файл, открыть разговор с агентом, помнить состояние вида и дать
тему с иконками. Тема — набор переменных, объявленный контрактом клиента: в редакторе его
заполняет vscode, в браузере — приложение.

## Возможности

Один и тот же сервер живёт в редакторе и в терминале, но умеет разное: терминал редактора
серверу из CLI недоступен. Поэтому сервер объявляет свои возможности, а клиент прячет то, чего
сервер не обещал.

## Транспорт и MCP

Контракт описывает вызовы и подписки, транспорт их переносит: `postMessage` внутри редактора,
http или stdio снаружи. Подписки — часть контракта, поэтому транспорт обязан уметь поток: карта
следится на файловой системе и сама говорит, что изменилась.

MCP — ещё один транспорт к тем же юзкейсам, а не вторая реализация модели
([0009](../decisions/0009-mcp.md)). Расширение поднимает его при открытии карты, CLI — командой.

## Состояние

Стор метрик принадлежит серверу ([0013](../decisions/0013-metrics-store.md)), а сервер поднимает
тот, кому он нужен: у окна редактора свой, у CLI свой. Общего состояния между ними нет.

## Где сейчас код

Переезд состоялся: модель карты, сбор метрик и стор живут в `abstract-server`, интерфейс —
в `abstract-react-client`, контракт и типы — в `core`. Приложения остались тем, чем должны:
`vscode-extension` реализует порты обеих сторон, `cli` — порты сервера.

В редакторе осталось то, чего нет нигде больше: терминалы с сессиями агента, диалоги, поиск
карт по папкам воркспейса и подстановка темы в переменные клиента.
