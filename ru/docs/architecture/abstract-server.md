# abstract-server

Юзкейсы и домен карты. Среда приходит портами, поэтому один и тот же сервер работает в
редакторе и в терминале. Решения [0014](../decisions/0014-client-server.md) и
[0015](../decisions/0015-package-layout.md).

Архитектура функциональная: домен — типы и чистые функции, юзкейс — функция, принимающая
порты. Классов и контейнеров нет.

## Структура

```
src/
  entry/                точки входа, сборка всего вместе
  features/
    <feature>/
      index.ts          что фича отдаёт наружу
      application/
        use-cases/      функция принимает порты и оперирует доменом
        services/       переиспользуемое между юзкейсами, но не доменное
      domain/           чистые функции и типы по сущностям; value object — тоже тип и функции
  ports/                порты во внешний мир и между фичами
  kernel/               переиспользуемые доменные типы и функции
  lib/                  переиспользуемое, к домену не относящееся
```

## Правила

Реализаций портов в пакете нет. Они живут в приложениях (`vscode-extension`, `cli`) или в
отдельных пакетах — так устроен `mcp`: набор адаптеров, а не второй сервер.

Внутренние порты наружу не экспортируются: наружу смотрит `index.ts` фичи и точки входа.

Домен ничего не знает про порты: порт получает юзкейс и передаёт домену уже данные.
