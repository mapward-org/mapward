# Расширение VS Code

Приложение: реализует порты сервера и клиента и связывает их с редактором. Внешний контур —
[`packages.md`](packages.md), правила слоёв — решение
[0015](../decisions/0015-package-layout.md).

## Структура

```
src/
  apps/            точки входа. Не реализуют бизнес-функции: связывают фичи и запускают
    extension/     рантайм расширения — vscode api, файлы, терминалы
    webview/       рантайм вебвью — react, отрисовка
  features/        крупные независимые единицы функций
    feature/
      index.extension.ts   public api для расширения: всё явно, без `*` в импортах
      index.webview.ts     то же самое для вебвью
      compose/     точки входа в модуль — компоненты, хуки, функции. Логики нет,
                   композирует model, ui, adapters, pure-model. Чистых реакт-хуков
                   и дивов здесь тоже нет
      _sub-module/ подмодуль, устроен так же
      model/       управление внутренним состоянием модуля — тем, которым он владеет
      adapters/    адаптеры к внешнему состоянию, которым модуль не владеет
      ui/          компоненты: вёрстка и, самое большее, состояние отображения
      pure-model/  типы и чистые функции
  kernel/          связующий слой фич: только типы, чистые функции, порты, контексты
  shared/          переиспользуемые модули без бизнес-информации. Чётких правил нет,
                   но декомпозированы по low coupling / high cohesion
```

Стили собирает tailwind из `apps/webview/index.css`, и он же подключает разметку клиента
директивой `@source`: сам tailwind ищет классы только рядом с входным css, а она живёт в пакете.
Забыть эту строку — получить сайдбар из голого текста при зелёной сборке, поэтому её стережёт
`tests/webview-styles.test.ts`.

Вебвью в расширении два: вид в сайдбаре (`apps/extension/map-view.ts`) и табы объектов
(`apps/extension/object-tab.ts`) — решение [0026](../decisions/0026-object-tabs.md). Страницу им
собирает общий `webview-html.ts`, а сервер у них один на окно, поэтому таб и сайдбар видят одни
и те же значения метрик. На чём открыт таб, помнит сам вебвью: адрес лежит в его состоянии, и
после перезапуска окна редактор отдаёт его обратно сериализатору панели.

MCP-сервер карты поднимается здесь же: `apps/extension/mcp-http.ts` слушает петлю по http и
отдаёт юзкейсы сервера, а его адрес уезжает в `--mcp-config` при запуске терминалов — решение
[0009](../decisions/0009-mcp.md).

Кнопки этапов в файле директивы — фича `features/directive-buttons`: файл узнаёт себя в модели
карты и показывает этапы своего объекта. Сам запуск этапа у неё и у ряда кнопок на карте один —
`apps/extension/run-stage.ts`, где сводятся сервер и терминалы; получателя фразы выбирает фича
терминалов — решение [0032](../decisions/0032-stage-buttons-in-directive-file.md). Она же решает,
временные терминалы или постоянные: по тому, встал ли MCP-сервер на порт из `mcpPort`.

Список «ждут ответа» держит сервер, мост только передаёт его сайдбару (`watchTurns`,
`dismissTurn`). То же число `apps/extension/map-view.ts` ставит на иконку карты в левой полосе,
полем `badge` вида сайдбара: его видно и при закрытой панели — решение
[0034](../decisions/0034-directive-turns.md).

## Правило импортов приложения

```
apps -> features (feature|feature) -> kernel -> shared
```

Импорты через уровень разрешены.

## Правило импортов фичи

```
compose -> (model|adapters|ui) -> pure-model
```

**`model`, `adapters` и `ui` не импортируют друг друга** — связь только через `compose`.

Подмодули могут использовать `pure-model` родителя. Родитель обращается к дочернему
модулю только внутри `compose`.

```
compose -> _submodule -> pure-model
```

## `index` не содержит логики

`index.extension.ts` и `index.webview.ts` — только реэкспорт. Как только в них появляется
код, публичный api фичи перестаёт быть списком того, что она отдаёт, и становится ещё
одним местом, где живёт реализация: снаружи не видно границ фичи, а внутри — что откуда
берётся.

Так не надо:

```ts
// index.extension.ts
export function handlers() {
  return {
    watch: () =>
      new Observable((subscriber) => {
        const watcher = vscode.workspace.createFileSystemWatcher("**/config.json");
        watcher.onDidChange(() => subscriber.next());
        return () => watcher.dispose();
      }),
  };
}
```

Здесь в точке входа оказался самый платформенный кусок фичи — тот, который и должен был
жить в `adapters`. А так надо:

```ts
// index.extension.ts
export { handlers } from "./compose/handlers.ts";
```

Поток уезжает в `adapters/watch.ts`, сборка хендлеров — в `compose/handlers.ts`.

## Изоморфность

Расширение живёт в двух рантаймах: extension host знает `vscode`, файлы и терминалы,
вебвью умеет только рисовать. Инкапсулируем по фичам, а не по рантайму: фича — это срез
функции целиком, и код внутри неё изоморфный.

Зависимости от рантайма живут **только в адаптерах**. Так удобно контролировать связность
и потом подменять реализацию.

`model` не имеет связей внутри себя, поэтому разные рантаймы через разные `compose`
тянут разные `model`. Два бандла получают по своей копии — это не рассинхрон, а
разделение владения: host владеет данными, вебвью владеет видом.

Наружу фича смотрит двумя файлами — `index.extension.ts` и `index.webview.ts`. Что
каждый рантайм видит от фичи, решает её автор, а не сборщик.
