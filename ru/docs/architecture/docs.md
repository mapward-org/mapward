# docs

Текст о том, как работает mapward, — тот самый, что читает пользователь и что агент получает
через MCP инструментом `read_docs`. Решение `0016`.

```
ru/                   markdown по разделам; папка на язык
scripts/
  bundle-docs.mjs     собирает markdown в модуль перед сборкой
src/
  index.ts            оглавление и раздел по имени
  content.generated.ts   собранный текст; в гит не кладётся
```

Слоёв здесь нет, и это не упущение: пакет не содержит логики — только текст и две функции
доступа к нему. Правила `0015` описывают раскладку кода, а раскладывать тут нечего.

## Почему текст собирается в модуль

Расширение собирается одним бандлом, и пути до `.md` внутри него не переживают сборку. Читать
доки с диска значило бы тащить через порты путь до собственного пакета — разный в редакторе,
в cli и в установленном виде.

Поэтому markdown остаётся источником для человека, а рядом генерируется модуль со строками.
Генерация идёт перед каждой сборкой и перед `typecheck`; результат в гит не кладётся, потому
что две копии одного текста расходятся, и правят всегда не ту.

## Язык — параметр с самого начала

Языков пока один, `ru`, он же умолчание. Параметр всё равно есть: добавить его потом означало
бы менять сигнатуры у всех, кто уже зовёт, и переписывать описание инструмента.

## Решений здесь нет вовсе

`decisions/` остаются у тех, кто mapward разрабатывает, и в поставку не входят. Поэтому в
тексте их нет ни ссылками, ни номерами: номер без ссылки отсылает читателя туда, куда он
попасть не может, и выглядит как знание, которого ему не выдали.

Правило простое: текст объясняет сам, почему устроено так. Не объясняет — значит написан
плохо, а не «подробности в решении».

Проекцией решений доки быть не перестают — источник истины по-прежнему там, разошлись, прав
решение. Просто видно это нам, а не читателю.
