## Из отзывов об MCP — отложенное

Сто восемьдесят один отзыв в `ru/mcp-reviews/` за 2026-09-20…23. Разобраны директивой
`2026-09-23-0322-анализ-mcp`, сделанное описано решением `0039`: реплику дописывает сервер,
сервер называет свою сборку и не глотает неизвестные параметры, промпт этапа не повторяется,
отзыв — один на сессию, битые и обратные ссылки — метрикой `links`. Здесь — остальное. Число в
скобках — сколько отзывов просили, примерно.

Отобрано по тому, ошибается ли от этого агент, а не по частоте. Всё ниже стоит лишнего вызова
или grep-а, но к неверным выводам не ведёт.

- **Код внутри пакета** (~35). Объект кончается на пакете, `files` отдаёт его целиком, и фичу
  агент ищет grep-ом. Просят объекты уровня фичи или метрику «фичи → файлы». Самая частая
  жалоба, но grep по папке пакета дёшев, а жалобу во многом создаёт промпт «читай карту, а не
  репозиторий».
- **Поиск по решениям и требованиям — «что решено про X»** (~20). Фаза противоречий на
  Брейншторме — grep по `ru/docs/decisions`. Механизм есть: `read-dir` с `content: true`.
  Рядом — «следующий свободный номер решения» с учётом номеров, занятых открытыми директивами (~7).
- **Интерфейс через MCP не проверить** (~14). Директивы про вид закрываются чтением кода:
  подсветку, стрелки, сайдбар MCP не видит. Просят ответ «что клиент показал бы».
- **Состояние треда** (~15, без того, что уже сделано). Дописал ли автор с прошлого прогона,
  висит ли незакрытый прогон (`startedAt` без `finishedAt`), отбор хвоста по разделу, а не по
  строкам.
- **Раскладка вкладок** (~11). `groups` без раскладки, состав вкладки после обоих фильтров
  сверяется по `_index.json`.
- **Ловушка `metrics: []` с `fields: ["metrics.key"]`** (~9). Отказ внятный, но наступают на
  него, сложив два рецепта из доки.
- **Метрика `files` без отбора** (~5): поддерево по пути, только изменённое по git.
- **Сервер падает посреди этапа** (~4): `finish_directive` не позвать, этап висит открытым.
- **Сцепка «директива → тронутые файлы»** (~8): какой прогон что поменял, пересечения
  открытых директив по файлам.
- **Связь «метрика ↔ на что она смотрит»** (~3): собрана ли ручная метрика до изменения своих
  файлов.
- **Отбор по конфигу по всей карте** (~5): «у кого в `transforms` стоит такой-то шаг».
- **Статусы требований машинно** (~6): сколько в каком статусе, что к какому объекту.
- **Метрика по самим отзывам** (~2): кластеры просьб со счётчиком, чтобы такой разбор был одним
  вызовом.
