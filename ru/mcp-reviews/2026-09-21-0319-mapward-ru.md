# Тестирование по `2026-09-21-0136-min-max-layout` на `mapward://`

## Чем пользовался

- `read_docs { section: "mcp" }` и `{ section: "directives" }` — как обычно, первым делом.
- `read_object { depth: 2, metrics: [], fields: [...] }` — обзор: сразу видно, что у директивы
  `run.stage: "Реализация"` закончен, а `runs` говорит, что «Проверка» и «Реализация» прошли
  по разу. Для этапа «Тестирование» это ровно тот вопрос, с которого он начинается.
- `read_index { file }` — текст директивы целиком (12.6 КБ, `tail` не понадобился).
- `read_object { depth: 3, fields: ["address", "metrics.key", "layout"], budget: 0 }` — главный
  вызов этапа. Инвариант решения `0029` («метрика объекта с раскладкой либо названа в `areas`,
  либо не показывается») проверяется им целиком, одним ответом на всю карту: ключи метрик
  у каждого объекта и `areas` верхнего. Без `budget: 0` ответ резался.
- `read_object { metrics: ["decisions"], refresh: "on-display" }` — новое решение видно на
  объекте, и у файла стоит `git: "U"`. Признак `git` у детей дерева оказался полезнее, чем
  ожидалось: не пришлось отдельно спрашивать, коммичен ли файл.
- `read_docs { section: "index-format" }` — и вот тут поймалось расхождение, см. ниже.

## Что не получилось

**`layout` приходит только у верхнего объекта — и это правильно, но для проверки инварианта
неудобно.** `0029` держится на соответствии «ключи метрик объекта ↔ имена в его `areas`», а
раскладка у раскрытых детей не приходит (как и `workflow`). Обзор с `depth: 3` дал ключи всех
объектов, но раскладки — только корня; остальные шесть пришлось читать с диска из
`_index.json`, склеивая пути руками. Довод про вес понятен, но `layout` — это не пять этапов
с путями, а одно небольшое поле, и, в отличие от `workflow`, у каждого объекта оно **своё**.
Удобнее было бы: `fields: ["metrics.key", "layout"]` отдаёт раскладку там, где её явно
попросили проекцией.

Отдельно: у объекта нет способа спросить «сколько строк в `areas` против токенов в
`gridTemplateRows`» — второй инвариант `0029`. Считать пришлось `node`-скриптом по семи
файлам. Это не просьба про метрику; скорее наблюдение, что проверяемые инварианты решений
проверяются мимо карты.

**Живой MCP отдал старую доку.** `read_docs { section: "index-format" }` вернул раздел «Высота
рядов» в первой, ошибочной редакции — с `minmax(0, 300px)` и «нижняя граница `0`
обязательна», — хотя в `packages/docs/ru/index-format.md` и в пересобранной
`content.generated.ts` лежит исправленный текст с `fit-content(300px)`. Это известное
(`ru/memories/живой-mcp-это-собранная-сборка.md`): сервер живёт в открытом расширении и отдаёт
то, что было на момент его запуска. Но ловушка здесь злее обычной: агент, который сверяет
правку с докой **через инструмент**, получает от инструмента свою же отменённую версию —
и по ней «убеждается», что правку не довели. Различить это в ответе нечем: ни времени сборки,
ни признака, что доки из `dist` старше исходников. Поле вроде `builtAt` рядом с `read_docs`
закрыло бы весь класс.

## Что сработало хорошо

`budget` с маркером `{ truncated }` — правильное поведение: с `budget: 0` вызов по всей карте
с ключами метрик весит немного, потому что значений в нём нет. Связка «`metrics: []` для
обзора → поимённая метрика с `refresh`» за этот этап не дала ни одного лишнего прогона
коллекторов.
