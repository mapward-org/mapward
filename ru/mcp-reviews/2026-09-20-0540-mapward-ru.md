# Прогон: «Реализация» по директиве 2026-09-20-0425-память-терминалов

Объект `mapward://`, этап «Реализация» — во второй раз: первый прогон сделал решение, требования,
конфиг и гайд, этот сделал код под два требования.

## Чем пользовался

- `read_docs { section: "mcp" }` и `{ section: "directives" }` — оба по одному разу, в начале.
  Раздел про MCP окупается: `fields`, `metrics: []`, `budget` из промпта не угадываются.
- `read_object { depth: 2, metrics: [] }` — обзор. Ответ 55 КБ, потому что `fields` я не назвал,
  хотя раздел прямо показывает вызов с ним. Свалилось в файл, разбирал скриптом. Второй раз
  звал уже с проекцией, и стало 2 КБ.
- `read_object` с `metrics: ["decisions"]`, `["requirements-todo"]`, `refresh: "on-display"` —
  проверить, что заведённое видно на объекте. Здесь метрика отвечает точно: 0018 в списке,
  оба требования в «черновиках».
- `read_index { file }` — текст директивы и экшона `implement-requirement.md`. Экшон достался
  от `prototypes/system`, и `owner` в ответе это сказал раньше, чем я пошёл бы искать файл.
- `run_directive` / `finish_directive`.

## Что не получилось

**Обзор без `fields` не влезает, и `budget` этого не чинит.** По умолчанию 24000, ответ пришёл
55 КБ: не режутся ни перечень метрик, ни поля объектов, а на корне карты их много. Раздел про
это честно предупреждает — но предупреждение читается уже после вызова. Помогло бы, если бы
`depth >= 2` без `fields` сам отдавал короткую проекцию, а полную только по явному списку.

**Кириллица в `read_object` приходит как есть, а консоль Windows её не показывает.** Ответ
сохранился в файл, `python`-разбор печатал `????`. Не вина MCP, но обзор карты на русском на
Windows читается только через файл с явным utf-8.

**Проверить правку кода через MCP нельзя.** Живой сервер — это `dist` открытого расширения:
после `turbo run build` вызовы отвечали по-старому. Пришлось прогонять `readMap` скриптом.
Это записано в память карты, но полезнее было бы, если бы `read_docs` или ответ сервера
называли версию сборки — тогда расхождение видно, а не выясняется опытом.

**`read_object` не показывает промптовые поля.** Ни `workflowPrompt`, ни новый `prompt` в ответе
нет, а `metrics.config` после подстановок — есть. Из-за этого нельзя проверить вызовом то, что
карта на самом деле скажет агенту: пришлось читать `_index.json` и собирать промпт руками.
Для этой задачи не хватало именно этого. Хорошо бы поле в проекции — `prompt`, после
наследования и подстановок.

## Что сработало

Директива с планом, написанным на прошлом этапе, — это готовый чеклист: по нему видно, что
из задуманного сделано, а чего нет, без пересказа. И `metrics.owner` с `owner` у файлов:
два места, где ответ сам говорит, куда идти править.
