# Отзыв: mapward:// — логи плагинов

Все этапы: Брейншторм (9 кругов), План (3), Реализация (4), Тестирование (3).

**Помогло**

- `read_run` после пересборки сразу показал, что прогон собирается из лога: проверка «хранилища
  больше нет, а инструмент работает» — один вызов.
- Сами новые логи: на Тестировании ход экшона, вложенные вызовы и трейс агента проверялись `grep`
  по `.mapward/logs/`, без отладчика и без вопросов к автору.
- Поле `build` в ответе `run_directive` (`builtAt`) — по нему видно, поставил ли автор свежую
  сборку, не открывая `~/.vscode/extensions`.

**Где потратил лишнее**

- Без `map: "Mapward (ru)"` вызовы молча уходят в первую карту (my-space) и отвечают «нет файла».
  Так же вызов MCP без карты пишет строку в лог первой карты, а не той, о которой разговор.
- Копии встроенных плагинов в карте перевёл на новое API раньше, чем поставил расширение: старая
  сборка не собрала их (`No matching export … TRACE_ENV`), и автор увидел поломку первым. Порядок
  «сначала поставить расширение, потом копии» есть в памяти, но про хуки набора, а не про сам
  `@mapward/plugin`.
- Проверка, перекрывает ли `--mcp-config` сервер из `.mcp.json`, стоила отдельного запуска
  `claude -p`: через MCP карты это не узнать.

**Что сделало бы дешевле**

- Предупреждение в ответе, когда `map` не указан, а карт несколько.
- Сборка плагинов карты могла бы называть версию `@mapward/plugin`, с которой собрана, — ошибка
  про отсутствующий экспорт сразу читалась бы как «старое расширение».
