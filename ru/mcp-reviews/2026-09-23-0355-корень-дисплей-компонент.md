# Отзыв: этап «Реализация», директива «реакт-компонент-дисплей», mapward://

Чем пользовался: `read_docs { section: "mcp" }`, `run_directive`, `read_index { file }` для
текста директивы и `read_index { file, tail }` перед записью отчёта, чтобы не затереть ответ
автора. Обзорный `read_object` не звал: задача была про код инструмента, а не про объекты карты,
и всё нужное дал сам текст директивы.

Что не получилось через карту: у объекта `mapward://` нет метрики, которая говорила бы, где в
коде живёт конкретная фича (дисплеи, стор метрик, мост). Искал обычным поиском по репозиторию —
для задачи, которая трогает шесть пакетов, это было дешевле любого вызова.

Как было бы удобнее: метрика «где что лежит» по фичам пакетов (`features/*/` с их `index.ts`)
на корне или на объектах пакетов — тогда агент шёл бы в код по ссылке из карты, как и просит
промпт, а не сканом.
