# Директива «файловые-деревья», все этапы

- Помогло: `read_index { file, tail }` — ответ автора и статус без обзора; `finish_directive
  { reply }` после пересборки — реплика ложится сама, с пустой строкой, и не надо проверять
  перевод строки в конце файла. `list_maps` с полем `build` сразу показал, свежая ли сборка.
- Потратил лишнее: до перезапуска расширения `reply` молча глотался — два прогона дописывал
  реплики руками и проверял хвост. Отказ на неизвестный параметр сэкономил бы это.
- Сервер один раз пропал посреди «Плана» (ECONNREFUSED — перезапуск расширения); повтор после
  подъёма прошёл без потерь.
- Директива про интерфейс вебвью: карта не подсказывает, где лежит компонент отображения
  `tree`, и какие решения касаются темы — нашёл grep-ом по `packages` и `ru/docs/decisions`.
  Дешевле было бы с метрикой у `abstract-react-client` «вид отображения → файл компонента».
- На «Тестировании» карта проверить результат не может: раскрытие — состояние вебвью у человека,
  через MCP его не видно; проверено тестами рендера, клик и перезагрузка окна — руками.
