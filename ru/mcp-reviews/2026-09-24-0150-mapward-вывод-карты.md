# Отзыв: директива «вывод карты» (превью объекта карточкой), mapward://

Этапы в этой сессии: План (шесть кусков), Реализация, Тестирование. Брейншторм шёл в прошлых
сессиях.

## Что помогло

- `read_index { file, tail }` на каждом круге Плана: по хвосту видно, ответил ли автор под
  последним куском, и файл целиком перечитывать не нужно. Поле `bytes` сразу показывает,
  дописалась ли реплика.
- `known` в `run_directive`: на пяти кругах Плана промпт пришёл один раз.
- `finish_directive { reply }`: реплика ни разу не прилипла к ответу автора.
- `read_object { fields: ["address", "groups"], metrics: [] }` — одним дешёвым вызовом видно,
  что после правки `_index.json` у объекта появились вкладки.
- `read_object … actions` дал адрес экшона «Собрать и поставить», и `run_action { wait: false }`
  запустил выпуск, не дожидаясь пятиминутной сборки.

## Где ошибся или потратил лишнее

- Код я читал обходом файлов, а не по ссылкам из метрик. Метрика `files` у `display` отдала
  дерево пакета, но у клиента фич много, и искать их было дешевле `grep`-ом по
  `packages/abstract-react-client/src`. Спросить карту «где живёт фича X» нечем: у фич клиента
  нет объектов на карте.
- `mapward object <адрес>` из CLI собирает все метрики объекта, в том числе дорогие, и висит
  дольше таймаута. Чтобы посмотреть вкладки объекта свежей сборкой, это не тот вызов. Нужен
  бы флаг «без метрик».
- Живой MCP отвечает старой сборкой, поэтому `defaultPreview` в `groups` не виден до
  перезагрузки окна. Это известно из памяти, но проверить новое поле MCP сейчас можно только
  подняв свой сервер по stdio, а этого я не делал.
- На Тестировании `finish_directive` закрывает директиву при любом вызове. Вопрос «коммитить?»
  пришлось дописывать в файл руками, мимо сервера, — ровно то, от чего `reply` должен
  избавлять.

## Что сделало бы дешевле

- Реплика без отметки о выполнении на этапе с `marksDone`.
- У `mapward object` — режим без сбора метрик, как у `read_object { metrics: [] }`.
