# Брейншторм по `2026-09-21-0246-улучшение-промптов.md`

Объект: `mapward://` («Mapward (ru)»).

## Чем пользовался

- `read_docs { section: "mcp" }` и `{ section: "directives" }` — как и велит промпт, первым делом.
- `read_object { depth: 2, metrics: [], fields: [...] }` — обзор. Дальше отдельный вызов с
  `fields: ["workflow", "actions", "layers", "prompt"]`: воркфлоу в обзорный набор полей
  не входит, а для директивы про этапы нужен именно он.
- `read_index { stage }` шесть раз — тексты всех этапов, не заводя прогонов. Ровно тот случай,
  ради которого параметр заводили: директива про промпты этапов иначе требует шести запусков.
- `read_index { file }` — текст директивы.
- `run_directive` / `finish_directive`.

## Что не получилось

- **MCP отвалился посреди этапа.** После чтения всех этапов `read_index` начал отвечать
  `Unable to connect. Is the computer able to access the url?` — и дальше так же. Текст
  директивы перед дозаписью перечитывал уже с диска, и отметку о конце этапа поставить нечем.
  Отдельно неприятно, что ошибка одинаковая для «карта закрылась» и «адрес не тот»: по ней не
  понять, ждать сервер или искать его.
- **Про сами прогоны MCP отвечает хуже, чем диск.** Счётчик `runs` приходит только у
  непрогнанных директив своего объекта, а вопрос был «какие этапы за месяц вообще звали» —
  это `runs` по всем 37 состояниям сразу. Считал скриптом по `_directives.state/`, мимо карты.
  Живёт это знание в карте, а спросить его нечем: `directives: "all"` вернул бы список с
  `runs`, но ценой всего остального в ответе.
- **Объём написанного этапом не виден ниоткуда.** Главный факт директивы — «Брейншторм пишет
  130 строк на 42 строки автора» — считается только чтением файлов директив глазами. Ни
  `bytes`, ни `runs` на это не отвечают: `bytes` — вес файла целиком, вместе с телом автора.

## Как было бы удобнее

- Сводка по этапам на объекте: сколько прогонов какого этапа было по всем директивам. Сейчас
  это единственное, ради чего пришлось лезть в `_directives.state/` руками, — а решение 0017
  говорит, что состояние прогона агента не касается.
- Различать «сервер не поднят» и «не достучались» в тексте ошибки. Первое лечится открытием
  карты, второе — адресом, и висеть с одинаковой формулировкой они не должны.
