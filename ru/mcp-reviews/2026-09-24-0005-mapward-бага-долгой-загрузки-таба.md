# Отзыв: директива «бага долгой загрузки таба» (mapward://)

Все этапы: Брейншторм (много кругов, с разворотом rxjs → MobX), План, две Реализации, Тестирование.

## Что помогло

- `run_directive` с `known` — промпт этапа на повторных кругах не приезжал заново, а кругов было
  больше десятка.
- `read_index { file, tail }` — хвост треда за один вызов; ответ автора виден сразу, без чтения
  всей директивы.
- `finish_directive { reply }` — ни разу не пришлось дописывать реплику файлом, и она ни разу не
  затёрла ответ автора, хотя автор писал в файл параллельно.
- `build.stale` в `run_directive` и `list_maps` — по нему видно, что живой сервер уже на новой
  сборке, и замер через его http-порт честный.
- Постоянный `mcpPort` в `mapward.json` — замер повторных вызовов удалось сделать скриптом прямо
  в живой сервер.

## Где потратил лишнее

- Устройство сервера (фичи, порты, кто зовёт `readMap`) карта не отвечает — пришлось читать код
  grep-ом. Метрика «кто кого импортирует» внутри пакета сэкономила бы полчаса.
- Сравнить новую модель со старой можно было только временным тестом со старым файлом из git —
  у карты нет способа спросить «как эту же папку прочитала бы прошлая сборка».
- Длинные правки через heredoc в Bash дважды потеряли обратный слэш и один раз не разобрались
  оболочкой; дальше писал код только `Write`. Это уже есть в памяти, но легко забыть.
- Тесты сервера берут `@mapward/core` из `dist` — после правки `core` упали на «не конструктор»,
  пока не пересобрал. Записал в память.

## Что сделало бы дешевле

- Метрика внутренних импортов пакета (фичи и их связи) — ответила бы на «где чья зависимость»
  без grep.
- Раздел доки MCP про то, как замерить время ответа живого сервера (порт, путь `/mcp`, формат) —
  собирал по коду расширения.
