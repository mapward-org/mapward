# Тестирование: доработки лейаута (mapward://)

**Чем пользовался.** `read_docs { section: "mcp" }`, `run_directive`, `read_index { file }` —
текст директивы целиком (8 КБ, `tail` не понадобился). `read_object` с `metrics: []` и
`fields: ["address", "layout", "groups"]` по `packages/abstract-server` — словарь раскладок
пришёл с ключами `min-width: 0px` / `min-width: 600px`, как в плане.

**Что не получилось.** Главное, что обещала директива, — прокрутка, прижатие кверху и
переключение колонок по ширине — видно только глазами в вебвью. MCP отдаёт раскладку как
данные, но не то, какой вариант сработал при текущей ширине и растёт ли сетка. Пришлось
проверять `grep` по `dist/webview.mjs` и `dist/webview.css`, что `@container`, `data-metric`
и `scrollbarSlider` доехали до сборки.

**Как было бы удобнее.** Для этапа тестирования UI — какой-нибудь снимок вида: ширина
области метрик у открытого объекта и имя сработавшего варианта раскладки. Тогда «в сайдбаре
одна колонка» проверялось бы вызовом, а не просьбой к автору посмотреть.
