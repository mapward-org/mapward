# Тестирование по директиве «серенький фон в табе»

Объект: `mapward://` («Mapward (ru)»). Этап «Тестирование», первый круг.

## Чем пользовался

- `read_index { file }` — текст директивы с разделом «Реализация»: по нему и шла сверка,
  пункт за пунктом.
- `read_object { address: "mapward://apps/vscode-application", metrics: ["architecture-drift"],
  refresh: "on-display", fields: [...] }` — посмотреть, не поплыла ли архитектура от правки.
  Отбор одной метрики по имени сработал как обещано: значение пришло целиком, без маркера
  усечения.
- `run_directive` / `finish_directive`.

## Что получилось хорошо

- **Метрика `architecture-drift` отвечает с `updatedAt`.** Четыре расхождения, которые она
  показывает, собраны до этого прогона и к правке отношения не имеют — и это видно по времени,
  а не по догадке. Без `updatedAt` пришлось бы считать их своими.

## Чего не хватило

- **Главное здесь не проверяется ничем.** Директива про то, как выглядит таб, а вердикт этапа
  собран из `lint / format:check / typecheck / test / build` и `grep` по `dist/webview.css`.
  Что фон в живом табе действительно стал сайдбарным, не подтверждает ни карта, ни прогон:
  живой MCP обслуживает старый `dist`, и увидеть результат можно только перезапуском окна.
  Для UI-директив это системная дыра — этап помечает выполненным то, что проверено наполовину.
- **Обещания директивы сверяются глазами.** Раздел «Реализация» — обычный markdown, и
  «пройди по обещаниям построчно» означает читать его и руками искать каждый файл. Пути в нём
  есть, но карта их не знает: связать пункт отчёта с файлом и его диффом нечем.
- **Отзывы затирают друг друга.** Файл `2026-09-21-0257-mapward-ru.md`, написанный на прошлом
  этапе, перезаписала параллельная сессия: в имени только дата, время до минуты и объект.

## Как было бы удобнее

Для UI-правок пригодилась бы метрика «сборка свежее исходников» — она бы отличала «правку
собрали» от «правку увидят после перезапуска». Сейчас это знание живёт в памяти карты
отдельным наблюдением, а не на объекте.
