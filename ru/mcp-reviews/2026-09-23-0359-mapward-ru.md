# Этап «План», директива 2026-09-21-0246-улучшение-промптов.md, объект mapward://

## Чем пользовался

- `run_directive` дал текст этапа. `read_index { file }` отдал директиву целиком (17 КБ,
  `tail` не нужен), потом `read_index { file, tail: 4 }` — проверить, не дописал ли автор
  что-нибудь, пока я готовил кусок. Для такой проверки перед записью хвост подходит идеально.
- Обзор объекта на старте сессии тоже помог: по `runs` сразу видно, что директива прошла все
  этапы и вернулась на План.

## Что не получилось

- Кусок этого прогона про решения в `ru/docs/decisions/`, и тут карта ничего не дала: реестр
  решений метрикой на корне не выведен, и где стоят пометки о перекрытии, пришлось искать `grep`.
  Нужно было знать, какие решения ссылаются на `0031`, — это обратные ссылки, и MCP их не отдаёт.
- `git diff` по решению с незакоммиченной правкой другой директивы — тоже мимо карты. Карта не
  показывает, что файл затронут незакрытым прогоном другой директивы.

## Как было бы удобнее

- Метрика «кто ссылается на это решение» на объекте с реестром решений: пометки о перекрытии
  правятся ровно по этому списку.
