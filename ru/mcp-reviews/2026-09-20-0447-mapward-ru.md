# 2026-09-20 — Mapward (ru), этап «План» директивы «Память терминалов»

## Чем пользовался

- `run_directive { stage: "План" }` — этап пропускает «Проверку», и карта не возразила.
  Правильно: порядок этапов — это порядок, а не зависимость.
- `read_index { file }` — директива с ответами, и `read_index` по экшону
  `add-requirement.md` с адресом `mapward://prototypes/system`. Второе сработало ровно как
  обещано в доке: файл лежит у прототипа, а я звал его по владельцу из `read_object`.
- `read_object` с `metrics: ["requirements"]` — группы реестра, чтобы назвать место для
  требования, не гадая.
- Дальше — обычный `grep` по коду. Метрика сказала бы, где лежит пакет, но я это уже знал
  из `props.codePath` прошлого вызова, так что за ссылкой не ходил.

## Что не получилось

- **Промпт объекта через MCP не отдаётся.** Я планирую поле, которое этот промпт дополняет,
  и не могу посмотреть, во что оно вольётся: `objectPrompt` зовут только из расширения
  (`bridge-handler.ts`), инструмента вроде `read_prompt` нет. Пришлось читать `prompts.ts`
  глазами. Для терминала, открытого мимо карты, это к тому же значит, что он промпта объекта
  не получает вовсе — а по `0017` такой запуск объявлен законным.
- **Метрика `files` не пригодилась ни разу, хотя задача была «посмотри код».** Мне нужны были
  четыре конкретных файла по именам сущностей (`workflowPrompt`, `objectPrompt`), а метрика
  отвечает деревом путей. `grep` по `packages/` нашёл всё за один вызов. Это не претензия к
  карте — просто честная граница: карта отвечает «где пакет», поиск отвечает «где строка»,
  и промпт это прямо говорит.
- **Историю этапов по-прежнему не видно** — четвёртый отзыв подряд с этим пунктом. Сейчас
  в директиве три раздела от трёх прогонов («Вопросы», «Вопросы — второй круг», «План»),
  а карта покажет один последний `run`.

## Как было бы удобнее

Этапу «План» нужно то же, что человеку на ревью: чем этот объект уже обвешан и что из этого
я собираюсь трогать. Первое карта даёт хорошо. Второго нет — связь «требование → файлы кода»
живёт только в голове того, кто пишет план, и в следующий раз собирается заново. Та самая
дыра, ради которой директива и заведена.
