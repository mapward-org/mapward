# Отзыв: директива «добавить вотчер в коллектор и трансформ», корень карты

Этапы: Реализация и Тестирование, одна сессия.

**Помогло.**

- `run_directive` сразу отдал текст этапа, а `read_index { file }` — директиву вместе со статусом.
  На Тестировании хватило `tail: 30`, чтобы увидеть, что после отчёта автор ничего не дописал.
- `finish_directive { reply }` дописал отчёт Реализации без ручной правки файла: тот кончался без
  пустой строки, и реплика не прилипла.
- Строка в памяти «в сервере первой идёт карта my-space» сберегла круг: я с первого вызова назвал
  `map: "Mapward (ru)"`.

**Где потратил лишнее.**

- Обзор объекта через `read_object` я не звал вовсе. Директива про код стора метрик, а у корня
  метрики, ведущей в `packages/abstract-server/src/features/metrics`, не нашлось, так что я пошёл
  grep-ом по пакету. Метрика «где лежит код фичи» на объекте пакета сберегла бы поиск.
- Живой MCP отвечает из установленного расширения (`build.bundle` в `~/.vscode/extensions`).
  Поэтому новое поле `watch` на карте через MCP не проверить: `stale: false`, но сборка старая по
  другой причине. Флаг `stale` про установленную копию молчит; пометка «бандл не из рабочего
  дерева» в `build` сразу сказала бы, что проверять вживую надо CLI-тестом.
- На Тестировании вопрос «коммитить?» нельзя отдать через `reply`, не закрыв директиву: пришлось
  дописывать его в файл руками. Параметр «реплика без закрытия» убрал бы и ручную правку, и заметку
  в памяти про эту ловушку.
