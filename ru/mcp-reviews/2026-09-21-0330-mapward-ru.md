# Реализация правок по директиве «исправить багу отображения метрик»

Объект: `mapward://` («Mapward (ru)»). Этап «Реализация», второй круг — по разделу «Правки».

## Чем пользовался

- `run_directive` / `finish_directive`.
- `read_index { file, tail }` дважды: перед началом — посмотреть, не дописал ли автор ответы
  на вопросы этапа «План», и перед дозаписью отчёта. Оба раза ответ пришёл за один вызов,
  и читать 59 КБ целиком не пришлось.
- Обзорный `read_object` и метрику `files` не звал вовсе: план прошлого этапа уже держал
  пути со строками, и этап свёлся к правке по списку.

## Что мешало

- **После правки кода карта о ней не знает.** Метрики `architecture-drift` и `decisions`
  считаются по диску, а живой MCP обслуживает `dist` открытого расширения — проверить
  «не поплыла ли структура» этим же прогоном нельзя. Пришлось сослаться на архитектурный док
  вместо метрики.
- **Номер решения снова считался глазами.** `0028` взят по `ls ru/docs/decisions`: карта
  список решений отдаёт метрикой, но «какой номер следующий» из неё не спросить. Это второй
  прогон подряд, где это стоило отдельного шага.
- **Кого перекрывает решение — по-прежнему grep.** Пометки в `0017`, `0019` и `0024` я нашёл
  поиском по папке; из карты обратных ссылок нет. Для этапа, который заводит перекрывающее
  решение, это ровно тот вопрос, который задают первым.

## Что было бы удобнее

Дешёвая метрика «решения» с полями «последний номер» и «кого перекрывает» закрыла бы оба
похода мимо карты. Сейчас `decisions` отдаёт список, а спрашивают у него не список.
