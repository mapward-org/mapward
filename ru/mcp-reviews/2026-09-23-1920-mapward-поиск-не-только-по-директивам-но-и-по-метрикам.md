# Отзыв: поиск на вкладке «об объекте» (mapward://)

Директива — чисто клиентская правка интерфейса, поэтому карта понадобилась в основном для
директивы и этапов, а код искался поиском по `packages/abstract-react-client`.

**Помогло.** `read_index { file, tail }` — хвост треда без чтения файла целиком, по нему же видно,
дописал ли сервер реплику. `run_directive` отдаёт промпт этапа вместе с полем `build`: по нему
сразу видно, свежая ли сборка отвечает.

**Где потратил лишнее.** На первых двух прогонах Брейншторма живой сервер был старой сборкой и
молча проглатывал `finish_directive { reply }`: вызов успешен, а реплики в файле нет. Первая
реплика пропала целый прогон, пока я не проверил хвост. Поле `build` появилось позже; с ним
это видно заранее.

**Что сделало бы дешевле.** Если бы `finish_directive` с `reply` возвращал, сколько байт дописал
(или путь и новый `bytes`), проверять хвост после каждого вызова было бы не нужно. Для правок UI
метрики объекта ничего не дали: у карты нет метрики «где лежит компонент такого-то экрана», и
путь к мета-экрану пришлось искать grep-ом.
