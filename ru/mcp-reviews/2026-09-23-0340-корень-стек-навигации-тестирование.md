# Отзыв: Тестирование, стек навигации по объектам (mapward://)

## Чем пользовался

- `run_directive` — текст этапа.
- `read_index { file, tail: 1 }` — узнать размер директивы (78 строк), потом целиком.
- `read_object { fields: ["address", "metrics.key", "metrics.value.ok"] }` — здоровье метрик
  `packages/abstract-react-client` одним дешёвым вызовом.
- `read_object { metrics: ["requirements"], refresh: "on-display" }` — убедиться, что новое
  требование видно на объекте.

## Что не получилось

- `read_index { file }` отдал `status: "new"` у директивы, которая прошла Брейншторм, План и
  Реализацию. Похоже, сжатие директивы сбрасывает статус или его считают по тексту, а не по
  `.state.json`. Сбивает, когда проверяешь, где директива.
- Проверить стрелки вживую MCP не может: интерфейс не его зона, а вебвью ходит в собранный `dist`.

## Как было бы удобнее

- Метрика требований весит много ради одной строки. Фильтр по `git`-статусу (показать только
  новые и изменённые требования) сразу отвечал бы на вопрос «что добавила директива».
