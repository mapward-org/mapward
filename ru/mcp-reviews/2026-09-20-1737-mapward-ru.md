# Этап «Брейншторм» по директиве `этап-воркфлоу-компактация`, объект `mapward://`

Третий круг подряд по одной директиве. Автор закрыл все семь вопросов второго круга и там же
задал встречный — «что собираешься делать», — плюс продиктовал формат, которым его надо
спрашивать: списки «Стоит учесть» и «Уточни», 3–4 вопроса, с контекстом вместо да/нет.

## Чем пользовался

- `run_directive` — промпт этапа и отметка о прогоне. Единственный вызов, который в этом
  заходе дал что-то новое.
- `Read` по файлу директивы с `offset`: хвост после правок автора. Через MCP текст приходит
  только целиком, а нужны были последние двадцать строк из двухсот.
- Память карты — `MEMORY.md` и `автор-отвечает-в-файл-во-время-сессии.md`. Второй файл в этом
  прогоне сработал ровно по назначению: предупредил, что текст в контексте устарел ещё до
  начала хода.
- Промпты этапов не перечитывал — остались в контексте с прошлого прогона.

## Что не получилось

- **Формат этапа разошёлся с тем, чего хочет автор.** Промпт Брейншторма требует «в каждом
  вопросе назови своё предложение, чтобы отвечать можно было одним словом», а автор прямым
  текстом попросил обратного: «проси у меня уточнения, а не оки». Писал по просьбе автора,
  против промпта. Это не баг MCP, но пока промпт не поправлен, следующий агент сделает
  наоборот — и будет прав.
- **Кругов много, а карта видит один.** `read_object` отдаёт `run` последнего прогона; что
  Брейншторм идёт третьим заходом, видно только по заголовкам разделов внутри текста. Для
  директивы, которая как раз про «когда пора сжимать», это главный недостающий факт.
- **Хвост директивы достаётся мимо карты.** `read_index { file }` отдаёт весь файл; чтобы
  прочитать только свежие ответы, я пошёл `Read` с `offset`. Третий прогон подряд с этим
  пунктом — и здесь он стоил не удобства, а точности: полная копия в контексте уже была
  устаревшей.

## Как было бы удобнее

- **Диапазон у чтения файла.** `read_index { file, from, to }` или хотя бы `tail` в строках.
  Тогда «что автор дописал после прошлого прогона» берётся из карты, а не `sed`-ом с диска.
- **Число прогонов по этапам в `read_object`.** Не история, а счётчик: `{ "Брейншторм": 3 }`.
  Сейчас признак «директива закружилась» существует только в глазах человека.
- **Сигнал о том, что слепок разошёлся с файлом.** Карта хранит копию текста на момент запуска
  и умеет сравнивать её с диском — из этого же получается ответ на вопрос «автор дописал
  что-то, пока этап шёл?». Флага в ответе `finish_directive` хватило бы, чтобы агент перечитал
  хвост перед завершением, а не по памяти о прошлых ожогах.
