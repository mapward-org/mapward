# Отзыв: mapward:// — управление картой как Miro

Сессия: Реализация (восемь кругов правок по живому холсту) и Тестирование, 2026-09-27.

## Что помогло

- `run_directive` с `known`: промпт этапа не приезжал заново на каждом круге — восемь кругов
  Реализации стоили одного промпта.
- `read_index { file, tail }`: новый круг автора лежит в последних строках, хвоста в 10–20 строк
  хватало всегда, файл в 45 КБ целиком не читался ни разу.
- `finish_directive { reply }`: реплика дописывалась в конец, хотя автор правил файл параллельно;
  проверка хвостом после вызова подтверждала, что она на месте.
- `metrics.logs` на Тестировании сразу объяснил красную вьюху: «Коллектор objects-map ещё не
  поддержан» — отвечает установленное расширение старой сборки, а не код.

## Где потратил лишнее

- Живой MCP всю сессию отвечал из установленного расширения, собранного до этой работы, поэтому
  результат ни одного круга через MCP не виден. Проверял вьюхи свежей сборкой через
  `node apps/cli/dist/cli.mjs metric <адрес>`. `build.stale: false` при этом честно говорит «файл
  не пересобирали», но не «сборка отстаёт от исходников» — это пришлось держать в голове.
- Зависание F5 разбирал по логам VS Code — MCP тут ни при чём, но первым делом хотелось спросить
  карту, какая сборка грузится в отладочном окне, а она знает только своё окно.
- Состав коммита: в индексе вперемешку правки нескольких директив и тестовые правки автора на
  холсте. Какие файлы тронула эта директива, карта не говорит — отбирал по `git status` вручную.

## Что сделало бы дешевле

- Поле в `list_maps` или `run_directive`: отстаёт ли загруженная сборка от `dist` в репозитории
  (не только от своего файла) — тогда «живой MCP этого не покажет» было бы видно сразу.
- Список файлов, тронутых прогонами этапов директивы, — для коммита на Тестировании.
