# Проверка директивы `новый-флоу-требований`, объект `mapward://`

Директива в две строки: «вычитывать требования отдельным этапом после плана бессмысленно,
убери это из описания флоу». Задача этапа — найти, где это описание живёт, и что его правка
ломает.

## Чем пользовался

- `read_docs { section: "mcp" }` и `{ section: "directives" }` — до первого обзора. Второй
  понадобился ради одного факта: где лежат этапы и что у них есть `marksDone`.
- `read_object { depth: 2, metrics: [], fields: [...] }` — структура и сводка директив. Сразу
  дал то, чего в директиве нет: пять этапов с путями и `owner`, и что открытых прогонов два
  (соседняя директива висит на «Плане» с 14:10).
- `read_index { file: "…md" }` — текст директивы. Единственный способ взять её по имени, а не
  путём; пригодилось, что в ответе есть `status: new`.
- `read_object { fields: ["metrics.key", "workflow", "actions"] }` — перечень метрик корня без
  сбора. По ключам (`requirements`, `requirements-todo`, `requirements-links`) сразу видно,
  что правка статусов заденет три метрики.

## Что не получилось

- **Промпты этапов пришлось читать с диска.** `workflow` отдаёт `path`, но `read_index { file }`
  ходит только по директивам и экшонам. Для этой директивы это было половиной работы: вопрос
  «что говорит про требования этап План» — центральный, а достать его текст можно только мимо
  карты. Наблюдение в памяти про это уже есть, и за сегодня оно всплывает не первый раз.
- **Экшоны так же.** `read_index { file: "add-requirement.md" }` формально умеет, но узнать,
  что экшон вообще есть, можно только через `actions` у объекта-владельца
  (`prototypes/system`), а не у корня, где выполняется директива. Я пришёл к ним грепом.
- **Реестр требований пришлось считать оболочкой.** Вопрос «сколько требований в каком
  статусе» — прямой вопрос к метрике `requirements`, но её значение это дерево лейблов для
  дисплея, а не сводка. `grep -rh "^status:"` дал ответ за один вызов и точнее.

## Как было бы удобнее

- `read_index { address, stage: "План" }` — текст этапа по имени. Проверка почти всегда читает
  соседние этапы: директива меняет флоу, а флоу — это и есть их тексты.
- Поиск по карте: «где упоминается слово X» в текстах директив, экшонов и этапов. Сейчас на
  вопрос «где описан флоу требований» карта не отвечает, а грепом он решается за минуту — и
  каждый такой обход уводит агента из карты в репозиторий.
- Счётчики по статусам рядом с метрикой требований (сделано / в работе / не начато). Дерево
  нужно человеку на экране, агенту нужна сводка, и она считается ровно там же, где дерево.
