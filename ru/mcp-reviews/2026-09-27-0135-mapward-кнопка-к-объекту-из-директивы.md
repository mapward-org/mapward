# Отзыв: mapward:// — кнопка к объекту из директивы

Все четыре этапа в одной сессии: Брейншторм (3 круга), План (5 кругов), Реализация, Тестирование.

## Что помогло

- `run_directive` с `known` — на повторных кругах промпт не приезжал заново, это заметно на
  восьми кругах Брейншторма и Плана.
- `read_index { file, tail }` — для чтения ответа автора хватало 3–4 строк хвоста; `bytes`
  сразу показывал, дописал ли автор что-то.
- `finish_directive { reply }` — реплики ложились в конец файла сами; на этапах без `marksDone`
  это полностью снимает ручную правку директивы.
- `read_docs { section: "directives" }` — объяснил, где живут кнопки этапов в файле; дальше в
  код пошёл уже прицельно.

## Где потратил лишнее

- Задача целиком про расширение и клиент, а метрики карты в код не вели — ходил `grep` по
  `apps/vscode-extension` и `abstract-react-client`. Обзорный `read_object` не звал вовсе:
  на корне он ничего не сказал бы о том, где лежат кнопки директив.
- На Тестировании нужна реплика без закрытия директивы (вопрос автору о падении F5) — такого
  вызова нет, вопрос дописал в файл руками, как советует память.
- Падение отладочного хоста (код 134) разбирал по логам редактора вслепую: карта про здоровье
  самого расширения ничего не знает. Метрика или экшон «запустить dev-хост и собрать его лог»
  сократили бы этот разбор.

## Что сделало бы дешевле

- Параметр `finish_directive { close: false }` (или отдельный вызов «реплика») для этапов с
  `marksDone`.
- Ссылка из объекта карты на код фичи директив в расширении — сейчас это знание только в
  памяти агента.
