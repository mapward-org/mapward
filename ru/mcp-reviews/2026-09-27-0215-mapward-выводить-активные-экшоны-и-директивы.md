# Отзыв: mapward:// — выводить активные экшоны и директивы

Этапы: Брейншторм (6 кругов + 1 после Реализации), План (4 куска), Реализация (2 круга), Тестирование.

## Что помогло

- `run_directive` с `known` — промпт этапа не приезжал повторно на каждом круге, а ответ автора
  брался `read_index { file, tail }` за пару сотен байт. Связка «known + tail» — ровно то, что нужно
  многокруговому треду.
- `finish_directive { reply }` — ни разу не пришлось править файл директивы руками ради реплики.
- `read_docs { section: "directives" }` сразу рассказал, как устроен список «ждут ответа» и экран
  прогонов, — вопросы Брейншторма опирались на это, а не на чтение кода.

## Где потратил лишнее

- Код искал `grep`-ом по пакетам, а не по ссылкам из метрик: обзорный `read_object` я не позвал ни
  разу — у задачи про клиент, сервер и расширение сразу нужен был обход фич, а метрики объекта
  отвечают, где пакет, а не где фича внутри. Дешевле была бы метрика «фичи пакета → папка».
- Живьём проверить ничего нельзя: MCP и вебвью отвечают из установленного расширения
  (`build.stale: true`), а новая лента живёт в свежей сборке. Проверка — только тестами.
- Правило слоёв клиента (эффекты и вычисления только в сторах) узнал по упавшему тесту
  `client-layers`, уже после написания вида. Ссылка на правило в доке MCP или в промпте этапа
  сэкономила бы круг.
- Heredoc с `cat > файл` без входа повис на две минуты — моя ошибка, не карты.
