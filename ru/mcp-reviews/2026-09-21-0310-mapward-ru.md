# План по директиве «исправить багу отображения метрик», второй круг

Объект: `mapward://` («Mapward (ru)»). Этап «План» по директиве
`2026-09-21-0031-исправить-багу-отображения-метрик.md`.

## Чем пользовался

- `read_docs { section: "mcp" }` и `{ section: "directives" }` — как велено промптом.
- `read_object` обзором на корне (`depth: 2`, `metrics: []`, `fields`) — сводка директив
  со статусами и `runs` сразу показала, что круг не первый.
- `read_index { file }` без `tail` — 38 КБ директивы целиком. Для этого этапа это было
  правильно: читать нужно снизу вверх, но ответы автора лежат вперемешку с вопросами
  прошлых кругов, и хвостом их не собрать.
- `read_index { file, tail: 14 }` перед дозаписью — проверить, не дописал ли автор
  чего-то, пока шёл этап.
- `read_object` на `packages/abstract-react-client` с `metrics: ["files"]` и
  `refresh: "on-display"` — дерево файлов со ссылками, по ним и пошёл в код.
- `run_directive` / `finish_directive`.

## Что мешало

- **Метрика `files` отдала весь пакет, а нужна была одна папка.** Ответ — почти 12 КБ,
  из них пригодилась десятая часть: `features/map-object`. Фильтра по поддереву у метрики
  нет, а `budget` режет значение целиком, не выбирая. Полезно было бы отдавать дерево
  от указанного пути — скажем, параметром рядом с `metrics`.
- **Метка `git` в дереве полезнее, чем кажется.** `"git": "M"` у файлов сразу показала,
  какие из них тронуты после прошлой Реализации, — это заменило `git status`. Стоит
  упомянуть её в разделе про метрики, сейчас о ней нигде не сказано.
- **Номер следующего решения приходится считать глазами по `ls`.** Решения — часть карты
  (метрика `decisions`), и «какой номер свободен» спрашивают на каждом планирующем этапе.
  Ответ «последний 0027, 0021 пропущен» MCP не даёт.
- **Перекрытые решения не видно.** Что `0024` уже переопределён в двух местах, нашлось
  грепом по `ru/docs/decisions/`. Из карты обратные ссылки «кого это решение перекрывает /
  кто перекрывает его» не спросить, а план на них стоит.

## Что было бы удобнее

Отбор поддерева у файловой метрики и обратные ссылки у решений закрыли бы оба похода
в обход карты, которые в этом прогоне были: `grep` по решениям и `ls` по их номерам.
