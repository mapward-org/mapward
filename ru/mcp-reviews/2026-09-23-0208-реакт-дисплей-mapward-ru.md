# Брейншторм «реакт-компонент-дисплей», второй круг, mapward://

Чем пользовался: `run_directive` (текст этапа), `finish_directive`. Директиву дочитал `Read` с
диска: хост прислал дифф изменений, а для правки `Edit` всё равно нужен прочитанный файл.

Что не получилось: решения и требования, с которыми надо сверить директиву (0014 — клиент и
сервер, 0027 — дисплей markdown, 0030 — расширение без внешних зависимостей, требование о форме
дисплеев), нашёл `grep` по `ru/docs/decisions` и `ru/requirements`. Через MCP вопрос «какие
решения касаются дисплеев» не задать: требования видны метрикой, но с привязкой к объекту, а не
к теме.

Как было бы удобнее: поиск по реестру решений и требований по слову или по объекту — хотя бы
список заголовков с адресами. Четвёртая фаза брейншторма («противоречия с решённым») целиком
держится на этом вопросе.
