# Отзыв: рефакторинг клиента, mapward://

Все этапы — брейншторм, план, реализация, тестирование.

**Помогло.** `run_directive` с этапом по имени отдаёт промпт целиком, без чтения файлов этапов.
`finish_directive { reply }` дописывает реплику сам — проверил `tail`, она на месте. Метрика
`requirements` на объекте клиента сразу показала новое требование с пометкой `git: A` — это и
была проверка «видно на объекте».

**Где ошибся.** `read_object { metrics: [], fields: ["metrics.key"] }` — отказ, хотя об этом
уже есть заметка в памяти; текст отказа сразу сказал, как надо. Стоило открыть заметку, а не
полагаться на строку индекса.

**Что дорого.** Сама директива большая: план и реализация шли по коду, MCP здесь почти не
нужен. Рантайм вебвью через MCP не проверить — баг «компоненты вечно собираются» увидел только
автор в редакторе. Метрика, которая рендерит клетку компонента в тесте (или хотя бы говорит,
что подписка на сборку открылась), поймала бы его до автора.
