# Отзыв: выводить активные экшоны и директивы — План, Реализация, Тестирование

Сессия продолжала директиву с середины: План (кусок 6), Реализация кусков 5–6, Тестирование.

**Помогло.**
- `read_index { file, tail }` — хвост треда за один вызов, с `bytes` и `status`; целиком файл читал
  только перед сжатием.
- `finish_directive { reply }` — реплика легла в конец без склейки с ответом автора; проверил
  `tail: 3`, всё на месте.
- `build` в `run_directive`: по `loadedAt` видно, что к Тестированию окно уже подняло свежую сборку,
  и проверка живого бандла свелась к `grep` по установленному `dist`.

**Где потратил лишнее.**
- Обзор объекта не звал: задача целиком лежала в клиенте, путь к фиче нашёлся поиском по строке
  заголовка «Идут и ждут ответа». Метрики, которая вела бы от пункта ленты к фиче клиента, нет —
  поиск по строке тут дешевле любой метрики.
- Тест слоёв клиента отбил компонент, который рендерит другой компонент внутри `ui/`; узнал об этом
  только полным `pnpm test` с корня. Память об этом тесте есть, но про правило «вью не рендерит
  вью» в ней ничего не сказано.
- Параллельная сессия своим снапшот-коммитом увезла мой незакоммиченный `turns-button.tsx`, и на
  Тестировании файл пропал из `git status`. Непонятно было, откатили его или закоммитили, пока не
  посмотрел `git log` по файлу.

**Что сделало бы дешевле.** Ленту («что идёт и ждёт») MCP не отдаёт намеренно, поэтому проверить
раскладку живьём агент не может — только тестом чистой функции и `grep` по бандлу. Для этой
директивы этого хватило.
