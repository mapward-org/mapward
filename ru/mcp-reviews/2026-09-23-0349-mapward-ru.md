# Отзыв: План по «улучшение-промптов», кусок 1

Директива: `2026-09-21-0246-улучшение-промптов.md`, объект `mapward://`, этап «План».

## Чем пользовался

- `read_docs` — `mcp` и `directives`;
- `read_object` — обзор на глубину 2, затем `fields: ["address", "workflow"]` на корне: вышли
  пять этапов с путями и `owner` — сразу видно, что все они лежат у `prototypes/base`;
- `read_index { file }` — текст директивы вместе со статусом;
- `read_index { stage }` — тексты «Сжатия» и «Реализации», прогон при этом не заводился.

## Что не получилось или было неудобно

- Кто ссылается на этап по имени (доки, решения, другие этапы), MCP не скажет — искал `grep` по
  репозиторию. Для правки, которая удаляет этап, это главный вопрос.
- Что в файлах этапа лежат незакоммиченные правки из другой сессии, видно только через
  `git status`. Карта этого не показывает, хотя для Плана это важно: следующий коммит их заберёт.

## Как было бы удобнее

- Обратные ссылки на этап или файл карты: «где упоминается `Сжатие`» — одним вызовом.
- Пометка «есть незакоммиченные изменения» у файлов этапов и директив в `read_object`.
