# Агент видит вкладки объекта и выбирает их

У объекта метрики бывают разложены по вкладкам, и агенту они нужны по той же причине, что
человеку: набор метрик, которые смотрят вместе. Решение `0025`.

`read_object` отдаёт перечень вкладок полем `groups` — ключ, подпись, описание и ключи метрик.
У объекта без вкладок поля нет вовсе, и это значит «показываются все метрики».

Параметр `group` отбирает метрики одной вкладки. Без него приходят метрики всех вкладок — и
только они: метрика, не названная ни в одной, агенту не приходит, как не показывается и
человеку.

Ключи, названные в `metrics`, побеждают вкладки: тот, кто зовёт метрику по имени, знает, что
просит.

Неизвестный ключ вкладки — ошибка с перечнем известных, а не откат на первую: отдать чужие
метрики под видом заказанных хуже, чем отказать. Вкладка спрашивается у названного объекта, а
не у всего поддерева: у детей вкладки свои.

## Сценарий

Агент зовёт `read_object` на пакете и видит `groups: [{ key: "код" }, { key: "тяжёлое" }]`.
Дальше он зовёт `read_object { group: "тяжёлое", refresh: "on-display" }` и получает метрики
одной вкладки, не поднимая остальных.
