# Документация едет вместе с инструментом

Чтобы понять, как устроен `_index.json`, как читается `mapward://` и из чего собирается
метрика, агент идёт в исходники. Это работает только там, где карта ведётся в репозитории
самого mapward: у того, кто его поставил, нет ни исходников, ни наших доков.

Поэтому текст про инструмент живёт отдельным пакетом и отдаётся через MCP: без параметров —
оглавление, с именем раздела — раздел целиком. Одной простынёй документация не отдаётся:
вываливать её в контекст значит ломать то, ради чего агент вообще называет поля и глубину.

Язык — параметр с самого начала, хотя значение пока одно. Решений в этом тексте нет ни
ссылками, ни номерами: `decisions/` остаются у тех, кто mapward разрабатывает, и номер отослал
бы читателя туда, куда он попасть не может. Док читается сам по себе. Решение `0016`.

## Сценарий

Агент, не знающий формата метрики, зовёт документацию без параметров и получает оглавление.
Дальше просит нужный раздел и читает его целиком.

Раздела с таким именем нет — в ответе сказано, какие есть.

Имя карты для этого не нужно: документация про инструмент, а не про карту.
