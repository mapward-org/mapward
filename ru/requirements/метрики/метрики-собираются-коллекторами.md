# Метрика собирается коллекторами

Коллектор берёт данные откуда угодно и отдаёт их дальше по пайплайну — решение `0004`.
Работают `static`, `script`, `read-dir` и `object-children-map`.

`script` запускается из корня карты и получает объект через переменные окружения
(`MAPWARD_OBJECT` и соседние): подстановка внутрь тела скрипта не дотягивается.

`read-dir` отбирает файлы глобами `include` и `exclude` и по флагу `content` отдаёт их текст —
без этого статус из файла не достать (`0010`).

## Сценарий

Кэш `collect.json` пишется, только если метрика его попросила: быстрому скрипту он не нужен,
а диффы в репозитории от него будут при каждом взгляде на карту.

Кэш лежит у объекта, даже когда конфиг пришёл от прототипа: определения наследуются, состояние
нет (`0002`). Иначе наследники делят одно значение, и объект показывает чужие числа.

Когда прогон упал, данные не затираются: пишется `ok: false` и новый `updatedAt`, а `data`
остаётся от прошлого удачного раза. Прошлое значение честнее пустоты.
