# Узел с файлом показывает, что о нём говорит git

Встроенный шаг `git-status` ставит узлам пометку: `M` изменён, `A` добавлен, `D` удалён,
`U` не отслеживается, `C` конфликт. Набор средний — staged и unstaged не разделяются, две
колонки порцелейна схлопываются в одну букву так, чтобы пометка читалась привычно тому, кто
видел её в редакторе. Решение `0023`.

Пометку получает всё, у чего есть ссылка на файл, какой бы коллектор её ни отдал: файловое
дерево, список требований, одиночная ссылка, узел карты. Ссылка на объект карты и ссылка наружу
не получают — за ними не файл.

Показывается она цветом имени и буквой справа: цвет — язык редактора, буква остаётся там, где
цвета не видно. Точка статуса метрики при этом на месте: это разные пометки про разное, и одна
другую не затирает.

Папка берёт сильнейшую пометку потомков, буквы у неё нет. Без этого свёрнутое дерево прячет ровно
то, ради чего на него смотрят, а буква на папке читалась бы как «изменилась сама папка».

Файл вне git, отсутствующий git и упавшая команда — пометок нет, и метрика от этого не краснеет:
причина уходит в `transform.logs.json`. Не сошлась пометка, а не данные.

Обновляется пометка сама: вотчер следит за `.git/index` и `.git/HEAD`, серия правок схлопывается
задержкой в триста миллисекунд. Агенту она приезжает тем же путём — внутри значения метрики
в `read_object`, отдельного канала для неё нет.

## Сценарий

Правка файла в редакторе: имя в дереве Файлов краснеет и получает букву, папки над ним красятся
тоже. Коммит — пометки уходят.

Переименование: новый путь помечен как добавленный, старого в дереве уже нет.

Карта, объекты которой лежат в разных репозиториях, работает: корень ищется по пути узла и
кэшируется, `git status` гоняется по разу на корень.
