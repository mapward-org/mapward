# Логи плагина пишутся в .mapward/logs

Всё, что плагин пишет — `ctx.log`, `ctx.log.error`, `ctx.output`, `ctx.step` и stderr процесса, —
ложится в `.mapward/logs/<папка плагина>.log`, откуда бы его ни позвали: кнопкой, метрикой, агентом
через `call_plugin`. Начала и концы трейсов и входы MCP — в `mapward.log`. Строка — JSON с трейсом,
номером вызова, объектом, плагином, методом, временем и видом записи; пишет их одна платформа.
Файл — до 10 МБ, предыдущий остаётся копией `.1`. Решение `0049`.

Агент читает логи путём к файлу; отдельного инструмента MCP для них нет.

## Сценарий

Метрика упала. Агент открывает лог её плагина, grep по объекту находит строку ошибки с трейсом, а
grep по трейсу — весь ход этого сбора.

Плагин, позванный `call_plugin` мимо экшона, всё равно оставляет ход в своём логе.
