## Задача

Разобрать все отзывы агентов о работе с MCP (`ru/mcp-reviews/`, 181 файл) и отложенные идеи в
`ru/docs/ideas.md` и решить, что сейчас сделать для улучшения MCP. MCP нужен агенту, поэтому
выбор — за агентом, автор слушает его доводы.

## Решено

- **Критерий отбора** — берём то, от чего агент ошибается или что ощутимо тратит ресурс, а не
  то, на что чаще жалуются. «Код внутри пакета», ловушка `metrics: []`, раскладка вкладок —
  стоят лишнего вызова, это в `ideas.md`, а не сюда.
- **Реплика в тред** — `finish_directive` принимает текст реплики и сам дописывает его в конец
  директивы. Правило «сервер только читает» на практике оказалось ненужным: запись в конец
  директивы разрешена.
- **Свежесть сборки** — сервер сам сообщает, из какого бандла он загружен и не устарел ли тот;
  неизвестный параметр вызова — отказ, а не молчание.
- **Промпт этапа** — не приходит повторно, если агент показал, что текст у него уже есть.
- **Обратные ссылки** — метрика «Ссылки» на корне: битые относительные ссылки в markdown и кто на
  какой файл ссылается. Упоминания решений в коде не ловим.
- **Отзыв о работе с картой** — только на этапе «Тестирование», один на сессию, итогом.

## План

1. **`finish_directive { reply }`.** Необязательный параметр. Передан — сервер до записи
   состояния читает файл директивы, добивает конец до пустой строки и приписывает текст; выше
   ничего не трогает. Без `reply` — как сейчас. Дописывание идёт раньше снятия копии, поэтому
   этап, помечающий директиву выполненной, снимает копию уже с репликой. Щель между чтением и
   записью в миллисекунды принята.
   Где: `packages/abstract-server/src/entry/mcp.ts` (схема, разбор), `entry/server.ts`
   (`finishDirective`), `features/map-object/application/use-cases/directives.ts` (дописывание),
   тесты рядом.
2. **Сборка и параметры.** Хост передаёт серверу путь к бандлу и время загрузки. `list_maps` и
   `run_directive` отдают `build`: откуда загружен, когда собран (время файла бандла), когда
   загружен, `stale: true`, если файл на диске новее загруженного. Неизвестный параметр —
   отказ с перечнем известных, проверка одна по схеме инструмента. Время сборки берётся по
   файлу, конфиги сборки не трогаются; метрика `agent-build` не меняется — она про диск,
   `build` — про процесс.
   Где: `packages/abstract-server/src/entry/mcp.ts`, `entry/server.ts`,
   `apps/vscode-extension/src/apps/extension/`, `apps/cli/src/cli.ts`.
3. **Промпт без повторов.** `run_directive` отдаёт `promptHash`; агент передаёт его параметром
   `known`, совпало — вместо промпта `unchanged: true`, отметка о начале прогона ставится как
   обычно. Отпечаток — по собранному промпту целиком, простая функция без зависимостей.
   Где: `packages/abstract-server/src/features/map-object/domain/prompts.ts`, `entry/server.ts`,
   `entry/mcp.ts`.
4. **Метрика `links`.** Скрипт обходит markdown в `ru/docs`, `ru/requirements`, `ru/memories`,
   этапах, экшонах и директивах карты, собирает относительные ссылки. Битые — список на экране,
   метрика красная; «кто ссылается» — в значении, для агента. Внешние ссылки и якоря не
   проверяются, выполненные директивы пропускаются. Корень проекта — аргументом скрипта.
   Пометки git — штатным шагом.
   Где: `ru/map/_metrics/links/` (`config.json`, `links.mjs`), `ru/map/_index.json` (метрика и
   группа «продукт»).
5. **Тексты, доки, решение.** Просьба об отзыве уходит из общего правила
   `ru/map/prototypes/base/_index.json` в конец этапа «Тестирование». Брейншторм и План отдают
   реплику через `finish_directive`. Доки `packages/docs/ru/mcp.md` и `directives.md` — про запись
   реплики, `build`, отказ на неизвестный параметр, `known`. Решение
   `ru/docs/decisions/0039` — одно на директиву; в решениях про MCP и про отзыв после каждого
   этапа — пометка о перекрытии. `ru/docs/ideas.md` — раздел об отзывах по новому счёту.
