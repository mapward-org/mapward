
## Задача

Метрика сейчас — JSON-пайплайн «коллектор → трансформ → дисплей» из базовых элементов. На практике
почти всегда нужен кастом; сбор без состояния медленный («Архитектура» в leafer — около 20 секунд
на каждый прогон); кэши коллекторов в git не нужны, а кэш и результат работы агента — разные вещи.
Mapward сейчас толстая платформа, а нужна тонкая: пути, иерархия объектов, базовый интерфейс. Сбор
и вид метрики пишет агент по месту — кодом сервера и клиента, а не JSON. Директивы, окна и экшоны
меняются меньше.

## Решено

- **плагин** — папка с кодом: серверная часть (долгоживущий процесс с состоянием), компоненты, методы. Объект или прототип подключает плагин и набирает из него нужное
- **процесс** — отдельный процесс на плагин на карту, не модуль внутри расширения: тяжёлое не блокирует карту и MCP, правка кода — перезапуск, свои зависимости, работает без редактора
- **плагины по модели shadcn** — строительные блоки пакетами (`@mapward/plugin` — сервер, `@mapward/display` — кирпичи и хуки), сами плагины копируются в карту и становятся кодом проекта
- **встроенные плагины** — реестр исходников при mapward, не код в платформе; копируются один раз (`init`, `add`), существующая копия не перезаписывается, обновление — явной командой с диффом
- **зависимости плагина** — свой `package.json`; `react` и `@mapward/*` отдаёт платформа; встроенные плагины без других зависимостей; без `node_modules` — понятная ошибка, карта живёт
- **запуск плагина** — node самой платформы, TypeScript собирает платформа esbuild-wasm; в проекте ни `tsx`, ни сборки
- **обращение к плагину** — только по пути от файла, где написан; имён нет
- **рабочая папка процесса** — папка плагина, гарантия; карту и проект плагин находит через `ctx`
- **жизнь процесса** — по умолчанию поднимается при первом обращении; плагин может объявить запуск вместе с картой и отключить гашение по простою; пересоздаётся только при правке кода, падении, простое
- **остановка** — новые вызовы не принимаются → все живые отписываются → `dispose(ctx)` → пауза → убить; `dispose` — вежливость, кэш обязан переживать внезапную смерть
- **скорость** — забота плагина; платформа не навязывает таймаутов (только у того, кто зовёт), очередей, сериализации вызовов, форматов кэша и стадий
- **кэш и артефакт** — целиком дело плагина; платформа ничего не разделяет и не хранит; соглашение: результат агента — коммитящийся файл, первое значение отдаётся из него сразу
- **деньги на агентов** — платформа не контролирует; согласие — сам код плагина; инструкция предупреждает про фоновые запуски
- **методы плагина** — каждый возвращает observable (`next`, `error`, `complete`, отписка); промис или генератор автор оборачивает сам; запрос это или подписка — решает плагин; отмена — отписка
- **контекст** — методы получают `(args, ctx)`, `init` и `dispose` — `(ctx)`; глобального API нет, метод тестируется с поддельным `ctx`
- **синхронно в `ctx`** — карта и корни, `resolve("mapward://…")` (чистая функция: адрес без решётки — путь), своя папка, лог, `isVscode`
- **асинхронно в `ctx`** — `object(адрес)` и `children(адрес)` из модели платформы (мердж и подстановки остаются в ней), observable с изменениями
- **плагин → плагин** — `ctx.plugin(путь)` через платформу: маршрутизация и подъём спящего процесса, одно состояние вместо двух
- **вызвавший объект** — в `ctx` его нет; объект и параметры передаются в аргументах
- **VS Code** — трогает только плагин: `ctx.isVscode` и ленивый неперечисляемый геттер `ctx.vscode` (без редактора — понятная ошибка); короткий набор: открыть файл, сообщение, терминал, подчёркивания, события, `executeCommand`
- **рукопожатие** — плагин отдаёт самоописание: методы, JSON-схемы параметров и значений, читающий или изменяющий, активация
- **метрика** — настройки (компонент, параметры с подстановками, `extends`), компонент, запрос для агента, скриншот
- **компонент метрики** — свой `.tsx` или компонент плагина с настройками; зовёт плагины `usePlugin<typeof api>(путь)` и адаптерами `useQuery` (результат), `useStream` (каждое значение), `useMutation` (по вызову); размонтирование — отписка
- **рамка метрики** — не обязательна; компонент сам показывает «не собиралось», «считаю», «упало»; кирпичи `NotCollected`, `Failed`, `MetricFrame`; за платформой — только граница ошибок отрисовки
- **честность значения** — ошибка observable не отменяет последнее значение, хуки держат его рядом с ошибкой
- **состояние по объектам** — плагин раскладывает его по адресу объекта, а не прототипа
- **кирпичи `@mapward/display`** — чистые: `List`, `FileTree`, `Link` принимают `onClick(item)` и ничего не зовут сами; `open(link)` из пропсов компонента уходит
- **навигация** — встроенный плагин `navigation` с `open(link)`, проверяемый с поддельным `ctx`
- **агенту** — метрика явно объявляет запрос для агента (метод плагина с параметрами); крайне желателен по промпту и инструкции, технически не обязателен; подробности агент берёт методами плагина
- **скриншот** — встроенный плагин `screenshot` (Playwright ставит сам при первом вызове), не платформа; отдаёт и ошибки консоли
- **изменяющие методы** — открыты агенту через MCP; в самоописании помечены; отмена — забота плагина
- **чтение через MCP** — обзор не будит плагинов; запрос для агента зовётся только у метрик, названных в `metrics` или `group`; `read_object` без `metrics` — ни одной метрики и подсказка
- **группы метрик** — остаются в `_index.json`: состав `metrics`, пометка превью и `layout` — ссылка на компонент раскладки (путь от файла или адрес); раскладка монтирует только то, что показывает
- **раскладка по умолчанию** — вертикальный список; сетка — кирпич `Grid`, её поле в `_index.json` уходит
- **экшон** — кнопка с формой над изменяющим методом: плагин, метод, параметры с подстановками, подпись, подтверждение; форма по JSON-схеме; свой компонент при надобности; `refreshes` не нужен
- **виды экшонов** — встроенные плагины `shell` и `agent`
- **история прогонов** — за платформой, только для вызовов через экшон
- **правка карты** — файлами, `edit_map` в платформе нет; модель производная от файлов, вотчер с дебаунсом; операции холста — методы плагина `objects-map`; сложные операции (перенос с переписыванием адресов) — функции `@mapward/plugin`
- **писателей много** — последний побеждает, атомарная запись через временный файл; холст держит свою правку поверх модели до подтверждения; реплику в директиву дописывает платформа
- **одна платформа на карту** — живая оставляет адрес в `.mapward/`, `mapward mcp` становится к ней тонким клиентом
- **доверие** — при первом обращении к новому плагину расширение спрашивает «Доверять?»; ответ у пользователя (`~/.mapward/trust.json`), не в репозитории; скопированное самим mapward доверено; консоль недоверенное не запускает; доверие по пути, не по содержимому
- **совместимость** — старый пайплайн временно живёт плагином `pipeline`; три карты (mapward, leafer, my-space) переводятся по одной, потом `pipeline` удаляется
- **для агентов** — команда проверки плагина и самоописание через MCP

## План

**solution — кто участвует и как договаривается.**

- Платформа — сервер карты, как сейчас: в процессе расширения или в консоли. Модель, вотчер,
  директивы, MCP, история прогонов экшонов, доверие. Метрик, коллекторов, стора значений и правки
  карты в ней нет.
- Плагин — отдельный процесс на плагин на карту; платформа запускает, останавливает и
  маршрутизирует. Один протокол поверх stdio в обе стороны: вызов, значения, ошибка, конец, отписка.
- Клиент рисует группы, раскладки и компоненты; с плагинами говорит через платформу тем же
  протоколом по мосту вебвью; редактора не трогает.
- Агент — через MCP: структура от платформы, данные и методы плагинов через неё же.
- Одна платформа на карту; файлы карты — общий источник правды.

Остальные куски плана не писались: автор попросил реализовать в отдельном worktree и обсуждать
готовый код.
