
## 

Добавь архитектурный док в каждый из пакетов будем туда дописывать по мере принятия решений
+ Метрики с сылками на этот док, и с валидацией архитектуры


1. core

```
core/
  contracts/ - Контракты разделение свободное от удобства
    contract-1.ts 
    contract-2
  lib/ - Переиспользуемые утилиты и типы. Например базовый дженерик для контрактов
    lib-1.ts
  model/ - переиспользуемые чистые функции и типы с доменной логикой в рамках нашей модели
    model-1.ts
  index.ts точка входа в пакет
```


2. abstract-server

Работаем в функциональной упрощённой версии чистой архитектуры

Где доменная модель просто типы и чистые функции, use-cases функции

```
entry/ - Точки входа, сборка всего вместе
features/
 <feature>/
  index.ts - что отдаётся наружу фичёй
  application/
   use-cases/
    use-case.ts - функция которая принимает порты и оперирует доменом
   services/ - переиспользуемя межу юзкейсами логика, но не доменная
    service.ts
  domain/ - Чистые функции и типы сгруппированые по сущностям. Так же можно сделать vo тоже через типы и связанные функции
ports/ - Порты взаимодействия с внешним миром и фич друг с другом. 
         Внутренние порты на ружу не экспортируются
kernel/ - Переиспользуемые доменные типы и функции
lib/ - Переиспользуемая логика не относящаяся к домену

```

Адаптеры портов будут в приложениях или отдельных пакетах (например mcp)

3. abstract-client 

```
entry/ - Точки входа, сборка всего вместе
features/
 <feature>/
  index.ts - что отдаётся наружу фичёй
  adapters/ - все зависимости на внешнее состояние. Например на глобал стейт.
  compose/
  model/
  ui/
services/ - переиспользуемы доменные модули
 <service>/
  index.ts - что отдаётся наружу сервисом
  adapters/
  compose/
  model/
  ui/

ports/ - Порты взаимодействия с внешним миром и фич друг с другом. 
         Внутренние порты на ружу не экспортируются
kernel/ - Переиспользуемые доменные типы и функции
lib/ - Переиспользуемая логика не относящаяся к домену

```
Смысл и правила ui model compose можно взять из текущеко vscode расширения

Важно: 
Мы работает в context first подходе, поэтому для доставки портов использовать можно контексты

Адаптеры портов будут в приложениях
