## Задача

Маркетплейс для mapward: плагины — основной способ расширять mapward, и своими плагинами удобно
делиться. Агент сам выкладывает плагин исходниками с документацией; другие агенты через MCP ищут,
читают исходники и ставят себе. Скачанное сразу не запускается — его проверяет агент или человек.
Маркетплейс в основном для агентов. Деньги («плагин за условный доллар») — когда-нибудь потом.

## Решено

- **Площадка** — без своего сервера: реестр поверх git. Свой сервис — когда появятся платные плагины.
- **Реестр** — отдельный публичный репозиторий в организации `mapward-org` на GitHub. Сверху —
  предупреждение, что за безопасность плагинов реестр ответственности не несёт.
- **Два индекса в реестре** — плагины и куски карты.
- **Публикация** — автор создаёт свой публичный репозиторий и pull request'ом добавляет ссылку на
  него в индекс. Инструмента публикации в MCP нет: рецепт в доках, агент делает всё через `gh`.
- **В индексе — ветка, а не коммит**: иначе каждое изменение пришлось бы принимать заново.
- **Проверка pull request'ов** — GitHub Action в реестре, без Claude: e2e ставит присланное в пустую
  карту и проверяет, что оно появилось и запустилось. Комментарии — только по форме, не по
  содержанию. Проверка исполняет чужой код без прав и секретов, принимает отдельный шаг.
- **mapward для проверки** — из npm. Организация `@mapward` в npm уже есть; выпуск CLI — в этой
  директиве.
- **Комментарии с предложениями доработок** — пока не делаем.
- **Установка** — разовое скачивание, как у встроенных плагинов: дальше это код проекта.
  Запоминаются ветка и коммит; агент может посмотреть изменения у автора и предложить новую версию.
- **Кусок карты** копируется в карту, а не подключается: любой агент может его поправить и
  проверить, конфликтов плагинов нет.
- **Безопасность** — всё в реестре — публичные репозитории, их читают до установки; карантина нет.
  Плагин из реестра при установке не доверен — редактор спросит «Доверять?».
- **Поиск, чтение, установка, сравнение** — прямо в MCP, доступны сразу без движений. Кому нужен
  другой маркетплейс — сделает свой плагин.

## План

**solution.** Кто участвует и как договаривается.

- **Реестр** — публичный репозиторий в `mapward-org`: два индекса, плагины и куски карты, и
  предупреждение сверху. Строка индекса — имя, описание для поиска, репозиторий и ветка.
- **Репозиторий автора** — публичный, один плагин или один кусок карты в корне, README для агентов.
- **Платформа mapward** ходит в GitHub только на чтение и без токена: индекс и файлы — по прямым
  ссылкам на содержимое, установка — архивом ветки, из которого же берётся коммит. Своего сервера нет.
- **Агент** зовёт инструменты MCP: найти, прочитать исходники до установки, установить, сравнить
  установленное с веткой автора.
- **Проверка реестра** — GitHub Action на pull request: ставит `@mapward/cli` из npm, заводит пустую
  карту, ставит туда присланное и проверяет. Проверка без прав и секретов, принимает отдельный шаг.
- **Публикация** — рецептом в доках: агент автора сам создаёт репозиторий и открывает pull request
  через `gh`, у платформы доступов к GitHub нет.

**platform.** Публичное API: четыре инструмента MCP и те же команды в CLI.

- **Найти** — по словам, в одном индексе или в обоих: имя, вид, описание, репозиторий, ветка. Ищет по
  имени и описанию из индекса, README не качает.
- **Прочитать** — по имени: без пути дерево файлов и README, с путём — файл. Ничего не ложится в карту.
- **Установить** — по имени. Плагин — в `_plugins/<имя>` (или названную папку), кусок карты — под
  названного родителя, нужные ему плагины ставятся первыми. Занятое место — отказ. Рядом остаётся
  запись «откуда»: реестр, имя, репозиторий, ветка, коммит.
- **Сравнить** — по установленной папке: что у автора поменялось с записанного коммита и чем
  локальная копия отличается от него. Обновление — не команда: агент переносит правки сам.
- CLI — то же самое (`mapward market search|read|add|diff`): на нём стоит проверка реестра.
- Настройки «не ходить в сеть» из доков в коде пока нет; маркетплейс её не вводит.

**software.** Модули.

- **Фича `market` в `packages/abstract-server`**, рядом с `plugins` и `map-edits`. В домене — чистое:
  схема индексов, поиск, запись «откуда», сравнение трёх состояний файлов (записанный коммит, ветка
  автора, локальная копия). В приложении — четыре сценария; MCP и CLI зовут их одинаково.
- **Сеть — портом**: индекс реестра, файл репозитория на ветке, архив ветки с его коммитом. Ходит в
  GitHub адаптер хоста; в тестах порт — словарь файлов.
- **Установка плагина — та же, что у встроенного**: сценарий принимает исходники снаружи и флаг
  «доверять» (встроенные — да, из реестра — нет). Защита занятой папки, порядок копирования и
  зависимости остаются общими.
- **Установка куска карты — правкой карты платформой**, пачкой с отменой: файлы куска пишутся под
  родителя, адреса внутри переписываются, как при копировании объекта. Плагины куска ставятся до
  пачки; упала пачка — плагины остаются.
