## Задача

Есть личная карта на все проекты, а часть информации хочется держать в карте в репозитории
самого проекта. Корневая карта должна подключать к себе карту другого проекта так, чтобы её
объекты могли ссылаться на объекты карты проекта и открывать их.

## Решено

- **что даёт подключение** — ссылки из родительской карты на объекты карты проекта и переход к ним; дерево не сливается, карта проекта в боковой панели не показывается вовсе — что нужно, покажут метрики
- **самостоятельность** — карта проекта про родителя не знает; открытая в своём репозитории, работает как раньше; внутри неё `mapward://` и `@` значат своё
- **виды ссылок** — все три: ссылка и связь на холсте, подстановка поля или метрики, наследование через `extends`
- **знак** — отдельный, двоеточие после имени: `mapward://leafer:/arch`, `mapward://leafer:/arch#props.name`, `mapward://leafer:@/src`; `leafer:~` — ошибка
- **где объявлено** — внутри записи карты в `maps`: `"mounts": { "leafer": "./leafer/mapward.json[0]" }` — путь к конфигу проекта и номер карты в его `maps`
- **объём** — не резать на несколько директив, делать целиком
- **открытие объекта проекта** — переходом на том же экране, а не отдельной вкладкой
- **ссылку на холст кладёт агент** — инструмента для человека пока нет и для своих объектов; он — отдельной директивой

## План

**1 · solution — как карты договариваются.** Подключения живут внутри записи карты в `maps`:
`{ "mapUrl": "my-space-map", "mounts": { "leafer": "./leafer/mapward.json[0]" } }`. Значение —
путь к конфигу проекта и номер карты в его `maps`, путь от папки родительского `mapward.json`.
Номер по позиции, а не по имени; без `[n]` — первая. Путь не на `mapward.json` или номера нет —
ошибка настройки у этого имени, остальные подключения работают. Карта проекта берётся со своим
корнем проекта, прототипами и настройками. Сервер поднимает её той же живой моделью, что и
обычную, но в список карт для панели она не попадает; одна карта поднимается один раз, узнаётся
по абсолютному пути. Деревья не сливаются: у каждой карты своя модель, у родителя — таблица
«имя → чужая карта». `mapward://leafer:/…` разрешается по таблице карты, которой принадлежит
объект со ссылкой, остаток адреса разбирает чужая карта по своим правилам. Подключения не
транзитивны. Проекта нет на диске — родитель работает, ссылки на это имя показывают ошибку на
месте.

**2 · software — адрес с именем карты и где он разрешается.** Разбор адреса в ядре получает имя
подключения перед двоеточием. Без имени адрес значит то же, что сейчас. Одна точка разрешения:
«адрес, написанный в такой-то карте» → «какая карта и какой адрес в ней»; дальше потребитель
работает с найденной картой как с обычной. Внутри системы объект определяется парой «карта + её
собственный адрес», адрес с именем — только форма записи в файлах родителя. Объект проекта,
открытый из родителя, открывается как объект карты проекта, его ссылки разрешаются от неё.
Обратного преобразования нет.

**3 · software — объект чужой карты на холсте родителя.** Вьюха получает второй вход — поиск
объекта по адресу с именем по снимкам подключённых карт. Чужие объекты попадают на холст только
ссылками и концами связей, отбор по `show` и прототипам — про свою карту. Чужой объект — всегда
один узел, не группа; рисуется по своим данным, помечено, из какой он карты. Связи, проведённые
на холсте родителя, пишутся в карту родителя с концом `leafer:/…`. Связи самого проекта между
двумя его объектами, лежащими на холсте родителя, тоже рисуются. Узел держит адрес в форме
записи родителя (ключ позиции и размера), а ведёт по паре «карта проекта + её адрес». Ссылка на
пропавший объект или отключённую карту остаётся узлом с ошибкой.

**4 · software — открытие объекта карты проекта в панели.** Переход на месте: запись истории
несёт пару «карта + адрес», экран берёт карту из текущей записи. «Назад» возвращает в родителя.
В крошках — родитель, имя подключения, путь внутри проекта. Живые модели карт на клиенте
заводятся по требованию, одна на карту на окно; карта проекта, на которую никто не смотрит, не
читается. Старая история одними адресами читается как записи своей карты.

**5 · platform — MCP и правка карты с чужими объектами.** MCP принимает адрес с именем везде,
где принимает адрес, и работает с объектом карты проекта; ответ говорит, из какой карты объект.
`list_maps` показывает подключения у родителя отдельным полем. `edit_map` на вьюхе родителя
принимает объекты проекта в `add-ref`, `create-relation`, `move-nodes`, `remove-ref`; перенос,
переименование, удаление объекта проекта через вьюху родителя — отказ с подсказкой.

**6 · code — живость и `@` у чужого прототипа.** Поиск в подключённой карте читает её живую
модель через наблюдаемые значения — правки проекта доезжают сами; пока она дочитывается, ответ
«ещё читается». Прототип из карты проекта наследуется по общему правилу: `mapward://@` в его
метрике — корень проекта наследника; код проекта — `mapward://leafer:@/…` явно. Дока (адресация,
настройка, MCP) и новое решение о подключённых картах — в Реализации.
