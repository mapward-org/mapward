Сейчас нет метрики - в каком состоянии находится объект.

Предлагаю сделать следующее 

Сделать прототип для всех самодостаточных объектов карты

В нём будут:

Метрика: требования - это файлы в которых описаны те или иные требования.
У каждого файла есть статус, который можно оттуда получить 

Метрика: Ошибочные требования - AI промпт который проверяет реализацию всех требований
Метрика: Требования для реализации: Все требования которые ещё не реализованы 

Нижние 2 метрики по умолчанию открыты и если нет таких выводят нет таких. Общий список требований 

Дальше экшоны:

- Добавить требование: Описание как создать файл с требованием и в какой он должен быть структуре. Содержимое требования может написать как агент по директиве так и сам человек по шаблону
- Имплементировать требование: Реализует требования в коде и проставляет нужный статус у требования

В месте с этим пропиши Расширению этот прототип и сделай требования что бы на них можно было протестить 


## Уточненеия

1. Файлы требований лежат в папке ru/requirements по пути куда ссылается code (Через префикс ru пока обходим проблему языка)
2. Текущие requirements давай раздеим на 2 части. Общее описание продукта остаётся, частности уже по поводу расширения уезжают в расширение. План убираем заменяем на не реализованные требования с нужными статусами. Часть вещей реализовывалась без плана. Можешь собрать директивы и добавить втребования
3. Статус в frontmatter. Статусы следующие: draft, ready-to-implement, implementing, implemented (Частичной имплементации нет). Ошибочная имплементация хранится не тут, а собирается напрямую промптом в отдельную метрику
4. Метрика ничего в док не ставит! Ставит в док статус экшон по результатам работы. Одна метрика выводит заявленое, вторая Реальное
5. Прототип инструмент. Будем приписывать туда где нужны требования
