## Задача

В метрике «Файлы» вызывать экшоны над файлами: переименовывать, удалять, создавать файлы и папки.

## Решено

- **кто выполняет операцию** — обычные экшоны карты, а не встроенные в дерево операции: история прогонов, запуск агентом, свои операции у других карт
- **несколько экшонов у строки** — меню строки по «⋯» при наведении и по правому клику; значков на строке нет
- **где записаны экшоны строки** — в самих узлах данных, списком; без предварительных оптимизаций вроде «экшоны по видам узлов в конфиге дисплея»
- **форма** — обычная форма экшона, упрощённой формы у строки нет
- **подтверждение** — нужен механизм подтверждения у экшонов: отдельное окно с вопросом
- **чем трогать файлы** — скриптами `script`, без нового встроенного шага: любой встроенный шаг надо поддерживать

## План

**1. software — у строки списка и узла дерева несколько экшонов.** Рядом с `action` (одна кнопка
прямо на строке) у строки появляется `actions` — список таких же ссылок на экшоны, это меню строки.
Старые данные остаются верными. Меню открывается кнопкой «⋯» при наведении и правым кликом по
строке — это одно меню, то же, что меню экшонов в шапке, без поиска. Запуск из меню — тем же путём,
что у любой кнопки; экшона нет — ошибка пункта меню, а не строки. Форма данных одна для `list`,
`tree`, набора `@mapward/display` и подсказки агенту.

**2. software — экшоны в узлы дерева «Файлы» кладёт скрипт-трансформ.** В общей метрике «Файлы»
между `read-dir` и пометками git стоит шаг-скрипт: файлу — «переименовать», «удалить», папке — ещё
«новый файл», «новая папка»; в форму уходит путь узла. Карта без файловых операций шага не ставит.
Создание в самой папке объекта — из меню экшонов в шапке, путь по умолчанию — папка объекта. Дерево
пересобирается само по слежению за файлами.

**3. solution — четыре экшона прототипа «Система» на node-скриптах.** Путь узла приходит из строки;
переименование спрашивает новое имя (по умолчанию текущее); создание — имя, можно вложенный путь,
недостающие папки создаются. Для всех: не выходить за папку объекта (её скрипт получает аргументом
из карты), существующее не затирать, удалять насовсем без корзины (страхуют подтверждение и git),
переименовывать без `git mv`.

**4. software — подтверждение с вопросом** (кусок не выкладывался, взято предложение Брейншторма).
`confirm` бывает текстом вопроса с подстановкой данных формы `${{ inputs.<имя> }}`. Перед запуском —
отдельное окно: вопрос, кнопка с подписью экшона и «Отмена», фокус на «Отмене». Есть незаполненные
поля — сначала форма, окно после неё. Агент через MCP такой экшон без `confirmed: true` не запускает,
а получает вопрос.

## Развороты

- Сначала предлагались значки частых операций на строке и упрощённая форма у строки — автор выбрал

- Предлагалось записывать экшоны по видам узлов в конфиге дисплея — автор отказался от
