
## Дополнение конфига лейаута

Обновляем решение 0003.

Сейчас раскладка не зависит от размера окна

Давай сделаем возможность указать несколько раскладок в зависимости от размера контейнера родителя

```
"preview-metrics-layout": {
    "max-width: 200px": { "areas": [], "style": {} },
    "max-width: 500px": { "areas": [], "style": {} }
} // Если не нужна адаптивность, старый вариант с areas на верхнем уровне тоже работает
```

Адаптивна раскладка целиком, а не только areas: style задаёт gridTemplateRows под конкретный
набор areas, врозь они разъезжаются.

Ключ уходит в CSS как есть — `@container (max-width: 200px)`. Ничего не парсим, доступны любые
условия container queries, а перекрытие разруливает каскад: побеждает последний подошедший
ключ. Значит порядок ключей значим.

## Добавление mapward.json 

Добавь отдельное решение про этот конфиг, и модифицируй решения по подстановке и резолвингу путей, модифицируй саму карту

mapward.json - файл настройки инструмента

Конфиг, который отлавливается cli и vscode расширением.
При запуске ищется в текущей директории и выше вплоть до корня


Основные 2 параметра

`mapUrl` - Указывает путь к директории карты
Дефолт mapward
`baseUrl` - Указывает путь, от которого будет резолвиться @
Дефолт .

Относительные пути в mapUrl baseUrl - резолвятся относительно mapward.json


`mapward://` - корень карты
`mapward://~` - текущий объект
`mapward://@` - ссылка на корень проекта
`mapward://@/packages/core` - ссылка от корня проекта

### Сценарии


Описание сценариев текстом человеческим. При переносе оформи более структурно

При установке расширения, добавляется иконка mapward в activity bar (самый левый таб)

При клике на неё:
1. Если есть mapward.json, то открывается корневой объект карты в сайдбаре
2. Если его нет, то показывается кнопка создать mapward.json


В корневом объекте расположено
0. Бредкрамбы по объектам с навигацией и кнопкой назад
1. Название объекта
2. Кнопка терминалы. Если терминалов нет, создаёт новый claude терминал в корне проекта (baseUrl) с базовым промптом, который указывает на объект с которым работаем. Если терминал есть то открываем выпадающий список терминалов с кнопкой создать новый и крестиком который закрывает терминал. У терминалов есть имя по дате времени или по директиве (см 4)
Терминал без директивы просто разговор об объекте. В базовом промпте. Совет правки делать через директивы

3. Кнопка экшоны. При клике на которую открывается список экшонов при клике на каждый открывается его файл
4. Кнопка директивы. При клике на которую открывается список директив с их статусами отсортированные по дате в имени файла, от новых к старым. Рядом с директивой 3 кнопки валидация тестовый запуск запуск. Просто клик по директиве открывает её файл. Кнопки создают терминал с клодом с нужным промптом. Статус директив новая, изменилась, выполнена
   По умолчанию клик по кнопке использует один терминал на директиву. Но при клике правой кнопкой мыши, можно выбрать вызвать в новом терминале или вызвать в другом существующем терминале
5. Кнопка создать директиву
6. Кнопка открыть объект как таб
7. Сетка метрик (адаптируется на основе конфига под ширину сайдбара)

Каждая метрика отображается индивидуально 

Если в метрике есть ссылка на дочерний объект он открывается
в сайдбаре или в выпадающем меню можно выбрать открыть в табе


Метрики:

Каждый тип display метрики — свой компонент с нужными пропсами

Если данные передаются не в нужном виде. Компонент выводит ошибку валидации

Коллекторы запускаются в зависимости от настройки, либо при рендере объекта, либо вручную. Интервалы запускаются при рендере объекта

Если у метрики есть updatedAt - значит нужно показать рядом с label время с последнего обновления мелко

У каждой метрики есть кнопка обновить (даже у запускаемых автоматом). Она появляется при наведении на label

Также при наведении на label появляется кнопка-тогглер скрыть, которую удобно использовать для скрытия карт (Скрывает содержимое, сам лейбл остаётся с кнопкой открыть)
Скрытие запоминается в персистентном хранилище (workspaceState расширения)

После запуска коллектора рядом с label появляется лоадер, при наведении на который крестик который прерывает операцию. 

После успешной синхронизации, просто показывается зелёная точка.
После неуспешной — красная. (Данные прошлые не затираются)

Запуск некоторых коллекторов порождает логи, они записываются в collect.logs.json при клике на зелёную или красную точку они открываются
(Логи трансформеров сохраняются тоже) В случае ошибки в трансформе появляется несколько точек на коллект и трансформ где по клику нужные логи

Информация об успешности прогона записывается в collect.json рядом с updatedAt

Пока данных нет - ничего не показываем и loader рядом с лейблом (В том числе пока читаем данные из кэша)

### Уведомления

У всех сессий клода есть доступ к API, который при вопросе или при окончании пуляет нотификацией в пользователя. При клике на которую открывается нужная сессия терминала
