## Задача

Готовые дисплеи метрики (текст, список, дерево и т.д.) в сложных случаях неудобны — например,
метрика процесса транскрибации видео: какие записи транскрибированы, какие нет, со ссылками на
файлы. Нужен дисплей — React-компонент, который пишет сама карта, со своими tailwind-классами и
любыми пакетами проекта. Позже из него будут запускаться экшоны объекта.

## Решено

- **вид дисплея** — новый `kind: "component"` в `display` метрики, поле `component` — путь к `.tsx`
- **схема данных** — поле `schema` в `config.json`: JSON-схема объектом или путь к `.json`; не прошло — метрика красная с путём до поля; агенту-трансформу схема уходит подсказкой
- **пути** — от папки того `config.json`, где поле написано, а не от наследника
- **безопасность** — не переживаем, код карты свой; в вебвью разрешаем `unsafe-eval`
- **сборка** — на сервере, esbuild в WebAssembly (`esbuild-wasm`), всё едет внутри расширения, без внешних зависимостей
- **пакеты** — от папки компонента вверх до `node_modules`, запасной путь — `node_modules` корня проекта; кратко описать в доке
- **React и набор mapward** — не вкладываются в сборку, их отдаёт клиент (одна копия React)
- **стили** — tailwind без нативного сканера: классы из прочитанных файлов проекта, css строит сервер, без preflight, цвета — переменные темы редактора
- **типы** — публикуемый пакет `@mapward/display`: `DisplayProps<Data>` и типы кусочков набора; кода в нём нет
- **проверка типов** — команда CLI `mapward display check <адрес метрики>`: генерирует `display.data.d.ts` из схемы, гоняет TypeScript, собирает компонент и проверяет последнее значение по схеме; в расширение TypeScript не тащим

## План

1. **Объявление.** `packages/core/src/model/schema.ts` — у `display` поля `component` и
   `schema`, вид `component`; `display.ts` пропускает данные `component` как есть. Пути
   разрешаются от папки слоя конфига, где поле написано. `shapeHint` в `abstract-server` у
   `component` кладёт в промпт схему. Схему проверяет сервер (`typebox`), ошибка — с путём.
2. **Сборка.** Порт сборщика в `packages/abstract-server/src/ports`: собрать файл с папками для
   пакетов → код, прочитанные файлы, ошибки. Юзкейс сборки дисплея в `features/map-object`:
   кэш до изменения прочитанных файлов, слежение за ними, ошибка сборки на метрике с файлом и
   строкой. `react` и `@mapward/display` — внешние. Вызов «дай собранный дисплей» в
   `packages/core/src/contracts`, подписка сообщает об обновлении. Порт реализуют
   `apps/vscode-extension` и `apps/cli` через `esbuild-wasm`, `.wasm` копируется в `dist`.
3. **Стили.** Тот же юзкейс после esbuild вытаскивает кандидаты-классы из прочитанных файлов
   проекта (не `node_modules`) и компилирует tailwind без preflight, в слое классов карты.
   Ответ — код и css. `tailwindcss` в `abstract-server` из общего каталога.
4. **Клиент.** В `abstract-react-client/src/features/map-object/_metrics` дисплей `component`:
   берёт код и css, выполняет код, подменяя `react` и `@mapward/display` своими, рисует
   экспорт по умолчанию; css — свой `<style>` на метрику. Пропсы: `data`, `object` (адрес, имя,
   `props`), `metric` (ключ, подпись, когда собрана), `open(link)`. Ветка в `ui/displays.tsx`,
   ловушка ошибок отрисовки. Политика вебвью — `unsafe-eval`.
5. **Типы и проверка.** Пакет `packages/display` (`@mapward/display`) с типами; клиент берёт их
   же. Команда `mapward display check`. Дока в `packages/docs/ru/metrics.md` (компонент, схема,
   пропсы, набор, стили, пакеты, пример, команда). Решение `0035` в `ru/docs/decisions`.
   Требование «метрика показывается своим компонентом» в `ru/requirements/ui/дисплеи` со
   сценариями. Тесты: сборка и стили на фикстуре, ошибка схемы, генерация типа из схемы,
   ловушка ошибок; нет внешних `require` в `dist/extension.cjs`.

## Развороты

- Схему сначала хотели во frontmatter компонента — у `.tsx` его нет, перешли на поле в `config.json` или ссылку на файл.
- Собирать хотели нативными esbuild и tailwind — установленное расширение без `node_modules` их не поднимет, взяли WebAssembly и сервер.
- Набор mapward сначала не публиковали — автор попросил публикуемые типы с дженериком под схему и команду проверки типов для агента.
