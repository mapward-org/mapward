Подстановки в конфигах карты

В любой строке `config.json` можно подставить адрес или значение.
Работает везде: `basePath` у read-dir, `run` у скрипта, текст промпта, `value` у static,
глобы. Так метрика прототипа работает у всех наследников без переопределения: путь
лежит в props наследника, конфиг метрики один на всех

```json
{ "kind": "read-dir", "basePath": "${{ mapward://~#props.codePath }}" }
{ "kind": "script", "run": "pnpm test --filter ${{ mapward://~#props.name }}" }
{ "kind": "static", "value": { "label": "code", "link": "${{ mapward://~#props.codePath }}" } }
```

Что писать внутри — в решении по адресации 0005

Формат с явными границами выбран, чтобы не сталкиваться с кодом в скриптах и промптах

```json
"${{ mapward://~#props.codePath }}"       // packages/core
"${{ mapward://~#props.codePath }}/src"   // packages/core/src, подставляется внутри строки
"${{ mapward://~#props.nope }}"           // ошибка, путь не разрешился
"node -e \"console.log($.a, ${x})\""      // как есть, одиночные $ и ${ не трогаем
"$${{ mapward://~#props.codePath }}"      // текст выражения, $$ снимает подстановку
```

Внутри тела скрипта данные объекта берутся из env — там подстановка уже не поможет

```json
{ "kind": "script", "run": "node -e \"console.log(process.env.MAPWARD_OBJECT)\"" }
```

Подстановка происходит после резолва extends, перед запуском пайплайна. Если путь
не разрешился, метрика не падает — показывает ошибку, как при несовпадении формы

### Подстановки работают и в `_index.json`

Никаких особых полей нет, `props` обычные данные

```json
{ "props": { "codePath": "${{ mapward://#props.basePath }}/packages/core" } }
```

Поле может сослаться на поле другого объекта, а то обратно — тогда получится цикл.
Ловим стеком вычисления и показываем ошибку в этом поле, остальная карта работает
