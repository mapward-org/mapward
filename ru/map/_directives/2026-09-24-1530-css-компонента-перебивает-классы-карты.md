## Задача

Css компонента метрики собирается tailwind-ом в тот же слой `utilities`, что у карты, и ложится
`<style>` после css карты. Повторённая утилита оказывается в каскаде ниже и перебивает соседнюю у
элементов карты: `p-2` компонента срезал `pl-6` у рамки сетки (`GridFrame`, `p-2 pl-6`), и стрелка
сворачивания уезжала за край (24.09, `mapward://actors/Пауль` карты my-space). После переделки
плагинов компонентами стали и встроенные метрики, у холста свой `p-2` — сломаться может любая
открытая клетка. Проверка — тестом: у открытой клетки с таким компонентом отступ рамки сетки не
меняется.

## Решено

- **актуальность** — проблема на месте и шире: компоненты теперь и списки, деревья, холст.
- **способ** — css компонента ограничен его территорией (`@scope`), а не слоем ниже и не
  выкидыванием повторов: оба те ломают сам компонент зеркально — у его `p-2 pl-6` побеждает `p-2`
  карты.
- **tailwind-merge** — не помогает: правит строку классов элемента, а ломает порядок правил в css.
- **граница — по метке, не по элементу клетки** — территория: элементы с меткой компонента; метку
  карта ставит на клетку и на слой для всплывающих окон, который выдаёт компоненту. Вынесенное
  прямо в `body` мимо слоя остаётся без стилей.
- **меню экшонов строки у списков** — рисуется в этот слой, а не в `body`.

## План

1. **platform — граница css компонента.** Css компонента действует только на территории
   компонента: элементы с его меткой и всё внутри них, кроме кусков самой карты, которые компонент
   вставил в себя (карточка объекта `ObjectCard` на холсте): внутри них опять css карты. Вложенный
   компонент — своя метка и своя территория, ближняя метка побеждает. Переменные темы tailwind в
   границу не попадают и остаются общими на страницу: значения те же, что у карты. Внутри
   территории компонент по-прежнему побеждает карту.
