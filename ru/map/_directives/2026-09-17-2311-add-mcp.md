## После обсуждения с агентом решили

Что сервер (http) запускается в момент открытия карты в одном процессе c расширением. Кэш и вотчинг шарится mcp с расширением

Запуск директив и терминалов получает mcp через --mcp-config (--strict-mcp-config не нужен. Оверкил сейчас)

В настройках mapward.json можно указать настройки для mcp которые фиксируют адрес который дальше используются другими агентами вне mapward
(Соответствующий mcp нужно будет дописать в .mcp.json в руками или через директиву)

MCP работает когда карта открыта. Потом добавим запуск mcp без открытия карты через cli, но сейчас открытая карта условие

так как расширение читает несколько карт. То mcp может тоже получить список и указать карту во всех обращениях.

Когда mcp нет, агент может запустить cli (которого ещё нет). Поэтому пока просто грустит 


> [AI] Запись остаётся файловой? По 0002 и промпту кнопки «запуск» агент обязан писать `_directives.state`. Если это остаётся `Write`, получается полкарты через API, полкарты файлами.

MCP - до появления cli становится единственным способом записать _directives.state через write теперь агент писать не будет. 


_directives.state - всегда пишется в git

collect.json тоже в гите, так как это часто результат промптинга, но кэш можно выключить (это уже есть в другом решении)

> [AI] 0002, Решение 5: extends может вести на внешний ресурс, то есть сервер при резолве ходит в сеть по содержимому репозитория. Оговариваем или запрещаем?

Давай базово может ходить, но нужно 2 настройки в mcpconfig - 
1. Не загружать вообще, (Карта вообще не ходит в сеть) 
2. Вторая не загружать из сетевых extends. То есть отключает транзитивные сетевые зависимости
(Кстати эти штуки действуют не только на mcp но и на саму карту. Так как mcp - копия карты)
