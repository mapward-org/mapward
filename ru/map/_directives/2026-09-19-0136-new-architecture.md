
## Давай: Добавим решение, потом обновим требования и добавим нужные объекты на карту со связями под новую архитектуру

Сейчас весь код наш лежит в одном приложении vscode, но уже появление mcp сервера и будущий cli толкает нас к развитию архитектуры


Предлагаю придти к клиент-серверной архитектуре. 

Но при этом - хитрой

У нас будет пакеты

core: Это слой связи клиента и сервера. Типы контрактов взаимодействия + Логика которая должна быть синхронизированна между всеми частями

abstract-server: Это абстрактный сервер который предоставляет юзкейсы и домен. Но ссылается на внешнее окружение через порты

abstract-react-client: Тоже абстрактный клиент, который рендерит реакт + tailwind но всё взаимодействие с платформой тоже через порты.  (Уровень абстрактности такой, что можно этот клиент отрисовать кк в vscode так и потом в web или desctop приложении)

mcp: Набор адаптеров для сервера, которые можно переиспользовать между платформами. Но сам он од платформы не зависит. Возможно не понадобится и всё можно просто положить в abstract-server

В apps у нас остаётся vscode-exctencion, но теперь оно в основном занимается имплементацией портов сервера и клиента

ТАк же появляется cli через который можно запустить mcp сервер или выполнить сервеную команду например получить метрику

Направление зависимостей

vscode | cli
     \/
 mcp 
     \/
 abstract-client | abstract-server
    \/
    core


## Уточнения
1. Смысл меняется, правятся доки
2. Пакеты лишние убираются, они шум от первой итеркации
3. Явно запиши, что выносим в core только при реальном прецеденте переиспользования, и если дублирование не подходит. Всё что выносится в core - проверяется человеком
4. Абстрактный клиент не знает ничего о сервере, только core
5. cli как и отдельное окно редактора поднимает свою копию стора. Конфликты write решать будем по ходу)
