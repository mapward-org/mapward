## План

### Что проверено по коду

- **Вид меню уже есть.** У `MenuButton` (`abstract-react-client/src/features/map-object/ui/
  menu-button.tsx`) в элементе списка есть поле `runs` — ряд маленьких кнопок, всплывающих под
  строкой по наведению. Оно осталось от прежних «проверить / сухой прогон / выполнить» и сейчас
  не используется ни разу. То есть этапы кнопками в ряд под директивой рисовать не нужно —
  нужно заполнить `runs` этапами из `current.workflow`. Мой вопрос 7 из «Проверки» снимается.
- **Отправка в живую сессию.** `openTerminal` (`vscode-extension/src/features/terminals/
  adapters/terminals.ts`) без `fresh` находит терминал и шлёт `singleLine(prompt)` без `claude`
  впереди. Это ровно то, что нужно кнопке.
- **Терминалы ключуются именем.** `byName: Map<string, vscode.Terminal>`, `freeName` вешает
  номер, `listTerminals` отбирает по префиксу `mapward: `. Переименование ломает все три.
- **Список объекту не принадлежит.** `bridge-handler.ts:69` — `listTerminals: () =>
  listTerminals({ prefix: "mapward: " })`: `address` из контракта выброшен, у каждого объекта
  видны терминалы всех объектов.
- **Сервер в окне один.** `main.ts` создаёт его и отдаёт и мосту, и `serveMcp`. Значит
  расширение может обернуть `finishDirective` своей функцией и узнавать о конце этапа, откуда
  бы он ни пришёл — из кнопки или из слов в терминале. Менять `abstract-server` ради этого не
  надо: переименование вкладки — платформенное, ему место в расширении (решения 0014, 0015).
- **Промпты живут в одном месте.** `prompts.ts` держит `objectPrompt` и `stagePrompt`, общая
  голова про MCP у них одна. Фраза кнопки просится туда же.

### 1. Решение

Правим `0017`, как договорились: раздел «Кнопок у директивы нет» остаётся на месте, следом
дописывается «Кнопка вернулась, но другая» — кнопка не заводит терминал и не несёт промпта, она
отправляет фразу в живую сессию объекта, а промпт по-прежнему приходит из MCP. Туда же —
известная дыра: живой терминал не значит живую сессию `claude`, и промах кнопки в закрытую
сессию мы принимаем осознанно.

### 2. Требования

Переписывается:

- `кнопок-у-директивы-нет.md` — предмет тот же, утверждение обратное, поэтому файл
  переименовывается в `кнопка-просит-агента-запустить-этап.md`: имя файла у нас и есть индекс.
  Текст: кнопка на этапе шлёт фразу в терминал объекта, промпт берётся из MCP, терминал не
  заводится, если он есть;
- `директивы-списком-со-статусами.md` — абзац про кнопки уходит совсем, остаются список,
  статусы и создание. Кнопки описаны в одном месте, а не в двух;
- `терминал-на-объект.md` — имя терминала перестаёт быть ключом: оно меняется, пока идёт
  этап, а различает терминалы идентификатор. Туда же абзац о том, что список терминалов
  объекта содержит только его терминалы.

Заводится одно новое, на `vscode-application`:

- `вкладка-показывает-идущий-этап.md` — по имени вкладки видно, что в ней идёт: объект,
  директива, этап; кончился — помечено завершённым. Запуск словами вкладку не трогает.

### 3. Код

1. **Терминалы по идентификатору.** Запись `{ id, address, name, terminal }`, ключ — `id`.
   `listTerminals` фильтрует по `address` (это и есть починка `bridge-handler.ts:69`),
   `freeName` нумерует внутри объекта, `showTerminal`/`closeTerminal` принимают `id`.
   Контракт моста и клиент переходят на `id`; в меню по-прежнему показывается имя.
2. **Фраза.** `stageRequest({ object, directive, stage })` в `prompts.ts` — одна строка вида
   «Выполни этап „Проверка“ по директиве 2026-…md на объекте mapward://…». Отдаёт её сервер
   новым методом, клиент её не сочиняет.
3. **Запуск этапа.** Новый метод моста: адрес, имя директивы, имя этапа. Расширение выбирает
   получателя — активный из терминалов этого объекта, иначе первый, иначе новый с промптом
   объекта, — показывает его, переименовывает и шлёт фразу.
4. **Переименование.** `workbench.action.terminal.renameWithArg` над показанным терминалом.
   Не сработало — пишем в лог и живём дальше: имя вкладки не повод ронять запуск.
5. **Кнопки.** В `map-object.tsx` у каждой директивы `runs` заполняется этапами
   `current.workflow`; идущий этап помечается по `file.run`.
6. **Завершение.** В `main.ts` сервер оборачивается: после `finishDirective` расширение
   находит терминал, которому оно отправляло этот этап, и дописывает к имени отметку
   завершения. Соответствие держится в памяти расширения, метка сессии не нужна.

### 4. Доки

- `packages/docs/ru/directives.md` — раздел «Как директива запускается» сейчас говорит
  «Кнопок у директивы нет». Переписывается: кнопка есть, она отправляет фразу, промпт всё
  так же из MCP. Это публичный текст, едет в пакете;
- `ru/docs/development-guide/directives.md`, раздел «Как запускаем» — что у нас кнопки этапов
  под директивой, а слова по-прежнему работают.

### Порядок

Решение → требования → терминалы по `id` вместе с фильтром по объекту → фраза на сервере →
кнопка в UI → переименование и отметка завершения → доки. Терминалы первыми: на их ключе
держится всё остальное.

### Чего в этом прогоне не делаем

- метку сессии в `--mcp-config`: запуск словами вкладку не переименовывает, это принято;
- определение живости `claude` в терминале через `shellIntegration` — записываем дырой
  в решение;
- уведомления от сессии: требование лежит `ready-to-implement` и делается отдельно.
