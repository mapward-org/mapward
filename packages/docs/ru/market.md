# Маркетплейс: плагины и куски карты от других

Плагины — главный способ расширять mapward, и своими удобно делиться. Маркетплейс — это место,
куда агент выкладывает плагин исходниками с документацией, а другие агенты находят его, читают и
ставят себе. Устроен он в основном для агентов: человек видит результат на карте.

Своего сервера у маркетплейса нет. Реестр — публичный репозиторий
[`mapward-org/market`](https://github.com/mapward-org/market) на GitHub, а то, что в нём
перечислено, — публичные репозитории авторов.

**За безопасность того, что лежит в реестре, реестр не отвечает.** Всё в нём публично и читается
до установки — это и есть проверка: агентом или человеком, прежде чем запускать.

## Что лежит в реестре

Два индекса — `plugins.json` и `maps.json`, массивы строк:

```json
[
  {
    "name": "deps-graph",
    "description": "граф зависимостей пакетов монорепы: метрика-дерево и холст",
    "repo": "author/mapward-deps-graph",
    "branch": "main"
  }
]
```

- `name` — строчные латинские, цифры и дефис: оно же папка плагина, `_plugins/<имя>`;
- `description` — по нему ищут, пишите его для агента: что плагин даёт и на каком проекте;
- `repo` — `владелец/репозиторий` или ссылка на GitHub;
- `branch` — ветка, по умолчанию `main`. В реестре ветка, а не коммит: автор правит свой плагин,
  не проходя приём заново. Коммит запоминает тот, кто поставил.

Репозиторий автора — одна вещь в корне:

- **плагин** — `index.ts` (`.tsx`, `.js`) с `definePlugin`, README для агентов и, если нужно,
  `package.json` с `dependencies`. Так же, как [встроенные](plugins.md#встроенные-плагины), он
  копируется в `_plugins/<имя>` целиком;
- **кусок карты** — папки объектов в корне, каждая со своим `_index.json`, как под корнем карты:
  обычно прототип с метриками, экшонами и этапами директив. Плагины из реестра, на которые
  опираются его метрики, — в `market.json` корня: `{ "plugins": ["deps-graph"] }`. Встроенные
  перечислять не нужно, но можно.

Внутри куска его объекты называют друг друга так, будто лежат под корнем карты:
`mapward://service`. При установке под родителя эти адреса переписываются —
`mapward://apps/service`, — значением, с хвостом `/…` и `#…` и внутри подстановки `${{ … }}`.
Чужие адреса (прототипы карты) и `${{ mapward:// }}/_plugins/…` не трогаются: плагины куска
ставятся в `_plugins` той же карты. Директивы куска не копируются — это история оригинала.

## Найти, прочитать, поставить, сравнить

Четыре инструмента MCP; те же команды есть в CLI, `mapward market …`.

| Инструмент | CLI | Что делает |
| --- | --- | --- |
| `market_search` | `market search [слова] [--kind plugin\|map]` | ищет словами по имени и описанию, в одном индексе или в обоих; без слов — весь индекс |
| `market_read` | `market read <имя> [файл] [--commit sha]` | без пути — дерево файлов, README и коммит ветки; с путём — текст файла. В карту ничего не ложится |
| `market_add` | `market add <имя> [--path папка] [--parent адрес] [--trust]` | ставит копией: плагин — в `_plugins/<имя>`, кусок карты — под родителя |
| `market_diff` | `market diff <папка>` | установленное против записанного коммита и ветки автора |

Обычный путь агента:

```json
{ "query": "граф зависимостей" }
```

`market_search` отдал имя — `market_read { name }` показывает файлы и README, `market_read { name,
path }` — код, который будет запущен, или команды в метриках куска. Прочитал — `market_add`.

### Установка

Поставленное — код проекта, как встроенный плагин: его правят, и mapward его не перезаписывает
никогда. Занятая папка или занятое имя у родителя — отказ.

- **Плагин** копируется без служебного (`.git`, `.github`, `node_modules`); его `dependencies`
  ставит npm, как у встроенного. Доверенным он **не** становится: до первого запуска редактор
  спросит «Доверять?». Агент в MCP доверия не выдаёт. В CLI доверить сразу можно флагом `--trust`
  — так ставит проверка реестра, и так ставите вы, если код прочитан.
- **Кусок карты** ложится одной пачкой [правки карты](mcp.md#написать-карту-методами--edit_map):
  ответ несёт `id`, и `undo_edit` по нему убирает кусок целиком. Плагины из его `market.json`
  ставятся до пачки — из реестра, а если их там нет, встроенные; уже стоящие не трогаются. Упала
  пачка — плагины остаются.

Двоичные файлы (картинки) не копируются — их называет поле `skipped` ответа.

Рядом с поставленным ложится `.market.json` — откуда и с какого коммита:

```json
{
  "kind": "plugin",
  "name": "deps-graph",
  "registry": "https://raw.githubusercontent.com/mapward-org/market/main",
  "repo": "author/mapward-deps-graph",
  "branch": "main",
  "commit": "4f1c…"
}
```

У куска такая запись — в папке каждого его объекта, с `top` и `parent`.

### Обновление

Команды обновления нет: копия — код проекта, и её могли поправить. `market_diff { path }`
отвечает, что изменилось: `commit` — записанный при установке, `latest` — коммит ветки сейчас, и
файлы с пометками `author` (поменял автор) и `local` (поменяли в карте) — `added`, `changed`,
`removed`. Совпали `commit` и `latest` — у автора нового нет. Дальше агент читает обе версии —
`market_read { name, path, commit }` и `market_read { name, path }` — и переносит правки автора
поверх своих, а потом поправляет `commit` в `.market.json`.

## Опубликовать

Инструмента публикации в MCP нет: публикация — это репозиторий и pull request от имени автора, а
доступов к GitHub у платформы нет и не должно быть. Агент автора делает это сам, через `gh`:

1. Репозиторий — публичный, плагин или кусок карты в корне, README для агентов: что даёт, какие
   параметры у методов и шаблонов, как поставить метрику. Перед публикацией —
   `mapward plugin check <папка>` у плагина и сборка метрик у куска.
2. Форк `mapward-org/market` и строка в `plugins.json` или `maps.json`:
   `gh repo fork mapward-org/market --clone`, правка, `gh pr create`.
3. Проверку делает бот реестра: GitHub Action ставит `@mapward/cli` из npm, заводит пустую карту,
   ставит туда присланное (`mapward market add … --trust`) и проверяет — плагин `mapward plugin
   check`, кусок — сборку и пробный запрос каждой его метрики. Зелёное — pull request принят,
   красное — комментарий с выводом проверки. Бот смотрит форму, а не содержание.

Дальше автор правит свою ветку как хочет, реестр об этом не знает.

## Другой реестр

`MAPWARD_MARKET` в окружении платформы — другой реестр: адрес, по которому лежат `plugins.json` и
`maps.json`, или папка на диске с ними. Так проверка реестра ставит строку из pull request'а, ещё
не принятого. Нужен совсем другой маркетплейс — это свой плагин.
