# Адресация и подстановки

Адреса объектов карты и пути к файлам легко перепутать, поэтому у карты своя схема. Она
говорит и откуда считаем, и что получим — путь или значение.

```
mapward://prototypes/package               путь до объекта от корня карты
mapward://prototypes/package#props.name    значение поля этого объекта
mapward://~                                путь до текущего объекта
mapward://~#props.name                     значение своего props
mapward://~/relations/relation             путь до ребёнка
mapward://@                                корень проекта — baseUrl этой карты
mapward://@/packages/core                  путь от корня проекта
```

Слэши идут по объектам, решётка отделяет путь по полям `_index.json`. Без решётки получаем
путь, с ней — значение. Пустой путь перед решёткой — корень карты: `mapward://#props.name`.

Код лежит вне карты, и чтобы не писать `../..` в каждой метрике, есть `@` — корень проекта,
то есть `baseUrl` из [`mapward.json`](config.md). Он свой у каждой карты и разрешается от той,
которой принадлежит объект. За `@` лежат файлы, а не объекты, полей `_index.json` там нет —
поэтому решётка с ним не работает.

Переезд карты правит одну строку в конфиге.

## Два способа употребления

**Ссылкой на объект** — значением поля, без интерполяции. Резолвится по месту: при
наследовании, при переходе, при валидации.

```json
{ "extends": "mapward://prototypes/package" }
{ "props": { "from": "mapward://core", "to": "mapward://vscode-application" } }
```

**Подстановкой в строку** — тогда адрес без решётки даёт абсолютный файловый путь.
Относительные пути в конфигах иначе не от чего считать: cwd инструмент не контролирует.

```json
{ "kind": "read-dir", "basePath": "${{ mapward://@ }}/packages/core" }
{ "kind": "script", "run": "pnpm test --filter ${{ mapward://~#props.name }}" }
```

## Подстановки

Работают в любой строке конфига: `basePath`, `run`, текст промпта, `value` у `static`, глобы,
и в `_index.json` тоже. Благодаря им конфиг метрики в прототипе один на всех: путь лежит
в `props` наследника.

```json
"${{ mapward://~#props.codePath }}"       // packages/core
"${{ mapward://~#props.codePath }}/src"   // подставляется внутри строки
"${{ mapward://~#props.nope }}"           // ошибка, путь не разрешился
"node -e \"console.log($.a, ${x})\""      // как есть: одиночные $ и ${ не трогаем
"$${{ mapward://~#props.codePath }}"      // текст выражения, $$ снимает подстановку
```

Явные границы `${{ }}` выбраны, чтобы не сталкиваться с кодом в скриптах и промптах.

Подстановка происходит после резолва `extends` и перед запуском пайплайна. Внутри тела
скрипта она уже не поможет — там данные объекта берутся из окружения.

Не разрешился путь — метрика не падает, а показывает ошибку, как при несовпадении формы.
Поле сослалось на поле другого объекта, а то обратно — цикл ловится стеком вычисления, ошибка
показывается в этом поле, остальная карта работает.

## Пути и ссылки наружу

В `extends`, `from` и `to` можно указать и обычный файловый путь, и ссылку в интернет.
Абсолютные пути разрешены и ничем не ограничены: что они не переживут переезда на другую
машину — забота того, кто их написал. Относительные резолвятся от cwd, а он непредсказуем,
поэтому надёжнее адресовать от корня карты.
