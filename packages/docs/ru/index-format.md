# `_index.json`

Файл объекта. Минимальный объект — папка с `_index.json`, содержащим `{}`.

```ts
type ObjectIndex = {
  name?: string                            // не задано — имя директории
  props?: Record<string, unknown>          // любые данные объекта
  extends?: string                         // mapward:// адрес прототипа или ссылка наружу
  "preview-size"?: { w: number, h: number }
  "preview-metrics-layout"?: Layout        // как объект выглядит карточкой на карте родителя
  "details-metrics-layout"?: Layout        // как он выглядит открытым
  "preview-style"?: CSSProperties
  prompt?: string                          // что карта говорит агенту на этом объекте
}
```

## `props`

Обычные данные, особых полей нет. Они уезжают в окружение скриптов, в промпты и в подстановки,
поэтому через них объект и договаривается с прототипом: `codePath`, `packageName`, `from`
и `to` у связи — всё это просто `props`.

Строки проходят [подстановку](addressing.md), в том числе внутри `props`.

## Раскладки

`areas` называют метрики по клеткам, как `grid-template-areas`; `.` — пустая клетка. `style`
уезжает в контейнер как есть — своего языка раскладки инструмент не заводит. Пишется любой
css: он не исполняется, максимум человек испортит себе вид.

Раскладки управляют только сеткой метрик. Где стоят имя, экшоны и директивы, решает код.

Разница между превью и деталями в том, как поступить с неназванной метрикой: на превью её
не будет, в деталях она покажется за пределами сетки. Превью — это витрина, туда попадает
только выбранное; детали — всё, что есть.

## Раскладка под ширину

Одна и та же карточка живёт в сайдбаре и в табе, ширина отличается в разы. Поэтому раскладок
можно задать несколько — по ширине **контейнера**, а не окна:

```json
"preview-metrics-layout": {
  "max-width: 200px": { "areas": [["code"], ["tests"]] },
  "max-width: 500px": { "areas": [["code", "tests"]] }
}
```

Ключ уходит в css как есть — `@container (max-width: 200px)`. Своего языка условий нет,
доступны любые container queries, а перекрытие разруливает каскад: побеждает последний
подошедший ключ, поэтому **порядок ключей значим**.

Адаптивна раскладка целиком, а не только `areas`: `style` задаёт `gridTemplateRows` под
конкретный набор клеток, врозь они разъезжаются.

Формы различаются по `areas` на верхнем уровне: есть — одна раскладка, нет — словарь.

## Мердж по `extends`

```
{ ...прототип, ...объект, props: { ...прототип.props, ...объект.props } }
```

`extends` резолвится рекурсивно, цикл — ошибка. Поля перекрываются целиком, `props`
домешиваются по ключам: наследник уточняет пути, не переписывая остальное.

Исключение — промптовые поля, `prompt` и `directives-workflow.prompt`: они складываются, от
дальнего прототипа к ближнему. Иначе объект, дописавший себе строчку, молча терял бы всё, что
базовый прототип говорит всей карте, — а заметить потерю нечем, потому что своя строка при
этом работает.

Мердж разрушителен: по результату не видно, из каких файлов он собран. Поэтому объект несёт
ещё и **слои** — список `_index.json`, от своего к дальнему прототипу. Слой назван адресом
и путём, конфига в нём нет: его читают по этому адресу.

Оттуда же это видно и в редакторе: меню конфигурации на объекте открывает мердж — тот, по
которому объект нарисован, вместе с развёрнутыми подстановками, — а под пунктом стоит по
кнопке на слой, и каждая открывает свой файл. То же самое, что у метрики с её `config.json`.

## `prompt`

То, что карта говорит агенту сверх сказанного инструментом. Инструмент знает себя, но не
знает, как устроена конкретная карта: где у неё лежит то, что читают перед работой, по каким
правилам её ведут, чего в ней делать нельзя. Это и пишется сюда.

```json
"prompt": "Память агентов этой карты — ${{ mapward://@ }}/ru/memories/. Начиная работу, прочти индекс."
```

Поле доезжает до обоих каналов: до промпта терминала, открытого на объекте, и до промпта
любого этапа его директив. Терминал и прогон — один и тот же агент на одном и том же объекте,
и правило объекта не зависит от того, запущена директива или нет.

Строки проходят [подстановку](addressing.md), поэтому путь внутри карты пишется адресом:
карта, переехавшая в другой репозиторий, остаётся рабочей.

Чем это отличается от `directives-workflow.prompt`: тот приклеивается **только** к этапам —
туда пишется то, что верно для прогона и бессмысленно в обычном терминале.
